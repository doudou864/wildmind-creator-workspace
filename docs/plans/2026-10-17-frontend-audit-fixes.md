# 全站前端审查修复实施计划

Goal：修复审查确认的十项问题，保持仅前端与服务契约范围，不新增依赖、不模拟业务保存成功。
Architecture：作品作为跨页关联主键；共用临时编辑保护；发布确认绑定材料版本；素材来源、用途和作品采用关系分开；总控台消费可追溯的任务与主题。
Tech Stack：现有 Next.js / React / TypeScript / YAML / Zod，沿用原生 Node 业务检查。

1. 新建 content-model 与作品接口、通用作品选择/新建控件，在选题、生图、排版、发布接入；排版携带 contentId。验证一个选题可创建多作品、关联冲突与未接入禁用。
2. 共用编辑会话保护，覆盖链接、历史前进后退、卸载；编辑期间保存只确认提交快照。验证后退返回不丢内容、延迟保存不吞新编辑。
3. 发布确认保存实际封面 ID/版本及材料指纹，服务请求带确认材料；刷新变化即重新核对。验证旧确认不得用于新封面。
4. 视频封面改为作品/比例显式采用关系，独立于 family 内部选版；素材上传提供用途，已有素材支持关联与用途编辑；上传图片可生成修改版。验证冲突可解除、手工封面可采用。
5. 按用途配置复用比例规则，生图与排版使用一致真实尺寸校验；补齐平台图文形式。
6. 总控台接入问题、计划发布、需求主题和账号异常的数据契约与跳转；私信待办按会话聚合，保留所有关联商单。验证未知与零值分开、主题同步失败不伪报成功。
7. 增加十项回归检查；执行原有检查、类型检查、构建和浏览器对抗验收，1440/1728 截图核查。更新服务契约、验收记录并提交本地 Git。

设计取舍：不新增作品独立板块；不使用浏览器持久化冒充数据库；离开页面时仅内存保留临时编辑，整页关闭仍提醒，页面明确区分临时恢复与保存。
