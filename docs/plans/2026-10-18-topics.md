# 选题后端 Implementation Plan

**Goal:** 接入既有选题界面，真实渠道一次生成 20 个候选，选择与 FIRE 定格持久化。

**Architecture:** 复用 TopicSignal、Topic 与生成记录表，Codex 只负责方向提炼和语义匹配；代码决定来源、去重、样本门槛、均值与原子入库。未同步消息不读取，未知来源不猜。使用现有调用层与数据库，不新增依赖或表。

**Tech Stack:** TypeScript、Drizzle SQLite、Codex SDK、Vitest。

## 实施与验收
1. 新建 `src/lib/topic-store.ts` 和 `.test.ts`。先测停用渠道、来源去重、D21 门槛与算术、数量及引用不合法整批拒绝、首次选择定格。短序号供 AI 引用，真实来源由代码回填。
2. `src/lib/workspace-service.ts` 读取真实选题，`src/app/api/topics/generate/route.ts` 调用生成，`src/app/api/topics/[id]/route.ts` 原子保存选择。生成过程文件锁避免同时重复提交；结果事务写入，失败有原因且无半批候选。
3. `src/app/topics/topics-page.tsx` 仅调整状态说明，探索位明确证据范围，未验证热度不虚称已验证。更新渠道文档中的过期占位说明。
4. 使用本机已登录 Codex 实际生成一批，查看来源与方向质量，检查只有启用渠道；未满20条D21不显示FIRE。临时测试库覆盖20条门槛，不污染真实偏好。
5. ego 两档截图自查；`npm run format`、`npm run check`。写D汇报、提交push后更新ROADMAP，继续第11步。真实发布素材目前缺失，不能用验收素材代替。
