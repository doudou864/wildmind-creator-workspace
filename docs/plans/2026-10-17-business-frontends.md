# 业务前端修正与生图中心 Implementation Plan

**Goal:** 将总控台、选题中心改为读取真实业务状态的前端，修正审核中的五项问题，交付 PRD 6.3 生图中心。

**Architecture:** 页面与业务 DTO 分离，服务器提供初始数据；写操作按单条资源提交并校验版本，定格字段由服务器事务保护。采集和 AI 未接入时返回明确的不可用状态，不注入演示数据。新页面沿用 src/ui 与 design.md。

**Tech Stack:** TypeScript strict、Next.js App Router、Tailwind CSS、ECharts、YAML、Zod；SQLite/Drizzle 与 Vitest 安装待用户批准。

## 已确认设计

用户明确要求后续实际使用的业务前端，并要求先修正审核问题、再开发生图中心。采用真实空状态 + 稳定接口 + 可持久化的本机业务操作；不继续演示场景切换，也不在本轮扩建平台采集或 AI 服务。视觉沿用现有参考，无须另选风格。

## 阶段一：修正

- src/lib/workspace-model.ts：逐检查点保存值、基线、样本数、采集时间、补抓/补录与缺失原因，D1 独立参与异常。
- src/app/dashboard.tsx：移除运行时演示资料，增加按平台/月/FIRE 分组的已定稿和预估命中率、分母和样本不足说明；详情展示检查点来源。
- src/app/topics/topics-page.tsx：使用业务数据、单条更新与冲突反馈；首次选择快照不可改；停用渠道不隐藏已存在候选；移除演示重置。
- 测试：两客户端冲突、首次定格、停用渠道恢复、D1/D3 阈值与空值、检查点补抓、命中率分组展示。

## 阶段二：生图中心

- config/image-styles.yaml：用途、默认比例、风格与历史参考来源规则。
- src/app/images/：用途、主题/正文、选题或作品关联、比例清单、草稿、聊天修改要求、版本列表、素材筛选与详情。
- 允许实际上传和选定版本（依赖批准后用 SQLite + 文件存储）；每个资产保留用途、真实宽高/比例、关联、来源、提示词、版本。
- 文章插图支持已有素材优先；视频封面固定三比例，公众号固定两比例；AI 生成及改图未接入时禁用并明确说明，不能产生假成功。
- 素材只出图/存库，不发布。

## 验收

1. 类型检查、正式构建、针对业务不变量的自动测试。
2. Ego 浏览器在 1440/1728 宽度检查三个页面，验证无演示数据、真实持久化、上传/选版/筛选/草稿恢复、不可用服务与错误反馈。
3. 所有破坏性测试使用独立临时数据目录，不清理用户业务数据；保存验收记录与截图；按阶段提交 Git。

## 用户补充决定
不安装新依赖。本轮只实现业务前端、DTO 与服务接口；存储/上传/AI 未接入时禁用操作且返回 503。不建数据库、不将演示 localStorage 迁入业务数据。业务逻辑使用现有 Node/TypeScript 执行针对性断言，不新增 src/core 算法。
