# 互动收件箱前端实施计划

目标：PRD 6.6 的业务前端与服务接口，不扩展到下一个商单列表页面；不新增依赖，不接真实采集/数据库/AI。

设计：顶部读取状态与筛选，左侧三分类与需求主题，中间消息列表，右侧原文/上下文/判定证据/交接状态。私信按消息保留分类，待回复汇总按平台+会话去重；评论独立判定。刷新只读本机记录，不触发额外抓取。已回复与同步选题是独立状态。

1. config/inbox.yaml、src/lib/inbox-model.ts、inbox-config.ts：分类结构、读取证据、待回复判定、筛选分页、主题来源与统计。
2. /inbox 页面与 src/ui/inbox.css：真实空态、评论/私信切换、平台/分类/回复/识别状态筛选、搜索、原文与上下文、商单自动流转说明、单条选题输入同步。
3. GET /api/inbox 与 POST /api/inbox/:id/topic。严格校验意图与修订号；未接入503。没有回复、删除、手动改已回复或触发额外采集的端点。
4. 原生测试验证回复证据、会话去重、分类异常、筛选与幂等边界；浏览器验收空态和隔离记录、接口失败、1440/1728截图；类型检查、构建。
5. README、接入契约和验收记录；git提交。

口径：列表一行代表一条收到的消息，私信会话可有多条消息；它们分别可成为选题输入，但待回复数量按会话去重。来源识别不完整时显示“待核对”，不猜测已回复。分类只有商单/有价值问题观点/其他三种，待识别/失败是识别状态。

完成记录：页面、配置、服务边界与接入契约已实现。21项新增业务断言、55项已有回归、6项HTTP检查、14项浏览器检查以及两种宽度截图通过；类型检查和生产构建通过。详情见 `docs/verification/2026-10-17-inbox.md`。
