# 下午采集与失败修复 Implementation Plan

**Goal:** 将北京时间主采集移到14:30–14:40，修复并发启动异常与已确认的采集缺口，用隔离测试及用户授权的真实只读采集验证。

**Architecture:** 保留现有launchd轮询与按平台独立进程，调度共享选择用SQLite短事务；失败不覆盖完整历史、不猜测指标。平台适配只根据实际页面证据修改，平台尚未更新与程序识别失败分开报告。

**Tech Stack:** 现有TypeScript、SQLite/Drizzle、Vitest、ego，不新增依赖。

## 1. 调度与进程互斥

- 修改config/parameters.yaml：主窗口14:30–14:40，重试15:00/15:30。
- src/jobs/schedule.ts及collect.ts：同日随机时间原子保存，窗口修改后沿用成功与已尝试状态，但更新启动分钟。
- src/jobs/lock.ts：释放与读取之间文件消失属于竞争，不报ENOENT；空文件可能正在写入，不误报损坏。
- 隔离回归：下午窗口、迟醒只执行最新时段、修改窗口不抹除成功状态、锁读写竞争。
- npm run format、npm run check，提交本步，再追加ROADMAP记录。

## 2. 平台适配与验收

- B站选择器等待真实标题/日期加载，区分空列表、缺身份和真实重复；真实页面确认后修改。
- 抖音列表缺少必需日指标时补读该作品详情；不改变检查点年龄或将null编造为0。
- YouTube保留过去28天范围，核对报表截止日期；缺作品先给准确数据延迟原因，不冒充当天完整采集。
- 小红书核对真实趋势图日期及悬停位置；不能把前天数保存为昨天。
- 视频号：用户明确允许桌面点击微信“允许”，但当前电脑工具已拒绝该浏览器地址，不能绕过；后台成功仍需页面核验。
- 隔离测试后运行完整check；用户已授权真实后台只读重新采集，记录各平台结果及未通过原因。无发布、无回复。

## 验收边界

本机定时器每次读取配置，无需新增Codex定时任务。真实平台数据晚于新窗口时仍如实失败并等待重试；下午采集不保证所有平台都已更新。用户已有config/选题输入渠道.md及ROADMAP未提交修改须保留，不混入本次提交。
