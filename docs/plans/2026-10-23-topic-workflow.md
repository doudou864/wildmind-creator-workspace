# 选题发现与观众角度工作流 Implementation Plan

**Goal:** 点击现有“生成20个候选”，使用来源库、主动搜索、抖音搜索词/看后搜发现实体，以观众收益或强烈好奇打磨角度，事实与兴趣分别复核，首轮只呈现句子。

**Architecture:** 保留后台任务、浏览器统一入口、SQLite事务和FIRE口径；新增配置化研究与编辑流程。一个浏览器任务内先浏览固定来源，再按已读线索与需求词搜索，并追进真实链接。模型只判断线索、搜索意图和角度，代码负责预算、链接校验、去重及状态。无需迁移或新增依赖。

**Tech Stack:** 既有 TypeScript / Next.js / Zod / Codex SDK / ego / SQLite / Vitest。

## 已确认决策

- 使用用户当前授权实施，不再次询问是否执行。优于只换一段生成提示词；也不新建无限循环的研究Agent。
- “与我有什么关系”：赚钱、方便、省时、学习、避损；或者一句话引起强烈好奇，想看实物/过程/证据。不是每题都赚钱，也不是每题都问为什么。
- 来源库是起点，不是白名单。允许站内/全网搜索；抖音关键词是实体/需求入口，一开始参与，不被新外站内容覆盖。
- 先兴趣后制作可行性，历史不限制方向；保留FIRE计算和冻结规则。探索位改为建议，不因配额不符扔掉合格题。
- 示例只用于角度校准，不能充当本轮事实。挂牌、成交、自述收入、可核实收益区分；旧热点不伪装成最新。
- 有预算的发现和一次独立编辑复核；登录/单站故障继续，用户接管停止。证据不足少于20并解释；不能承诺每批一定好看。
- 不修改现有用户渠道条目、不覆盖真实候选。测试用临时库和fixture，真实整轮生成待用户点击。

## 实施与验证（一个可验收步骤）

1. `config/topic-workflow.yaml` 与 `src/lib/topic-workflow.ts`：配置研究预算、入口、角度示例；结构化草稿和独立编辑筛选，验证每题实体/角度/观看理由/事实依据、删除重复。测试有趣但无证据、同实体同角度、搜索词误当事实等边界。
2. `src/browser/topic-source.ts`：页面可见链接取证、同一会话内追加研究页面、单页错误隔离。`src/lib/topic-discovery.ts`：只选择真实链接，搜索URL由配置和词生成；摘要不作为核实后的事实，限制预算并记录失败。单元测试预算/未知入口/链接/接管。
3. `src/lib/topic-store.ts`：合并内部需求与新来源，保留缓存日期，加入选择/跳过反馈，接入草稿和编辑复核；保存研究记录/原文，保留原子保存与历史选择。临时库贯通测试。
4. `src/app/topics/topics-page.tsx` / `src/ui/topic-generation-status.tsx`：新增阶段，默认只看选题句，依据点击展开，原有选择/跳过保持兼容。Ego隔离验收生成、防重复、刷新恢复、展开证据，两档截图。
5. 更新PRD、渠道规则（保留用户已有YAML）、design补充；运行定向测试、全量check、format、typecheck/build；提交本次代码，ROADMAP追加记录与证据。已有未提交播放图记录和用户渠道名单不纳入提交。

## 验收边界

自动测试验证流程和事实引用约束，不能证明主观吸引力或实际收益；仅网页入口只读实测不代表整轮真实采集通过。最终明确说明实际运行到哪一步。
