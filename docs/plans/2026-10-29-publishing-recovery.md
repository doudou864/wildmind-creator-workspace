# 发布任务恢复实施计划

**目标：** 修复浏览器工作区关闭后，继续处理和重新上传相互阻塞的问题，保留原材料与提交防重记录。

**设计：** 沿用原任务。继续处理先检查登记的浏览器：存在则按用户本次点击接回原工作区；不存在则说明原因，提供单独的“重建浏览器并继续上传”。重建仅适用于尚未进入发布提交的上传任务，后台再次确认原浏览器不存在后，重置已丢失的上传页面和审核截图，重新上传；材料及原始发布意图保留。旧平台私有草稿可能存在，不宣称已清理。已有提交意图/回执的任务拒绝重建，保留核对结果入口。删除任务时确认浏览器确实不存在即可完成清理，不再无限等待不存在的资源。

**取舍：** 不直接解锁顶栏“上传”，否则会绕过已有回执；不自动重建用户仍在控制的窗口。只在用户显式点击重建后执行恢复。

**技术：** TypeScript、现有 SQLite 状态与任务接口、Ego；不新增依赖或表结构。

1. 扩展浏览器恢复检查与任务控制：原空间接回、丢失空间重建、提交记录保护、并发版本保护。
2. 隔离测试验证丢失后可重启、已有空间不重建、发布结果未知不重传、删除丢失空间可完成。
3. 任务列表增加重建入口及处理中提示，错误和恢复结果留在对应列表；复用现有组件。
4. 运行格式化和完整检查；隔离页面点击验收、1440/1728截图；真实任务只检查状态，不以公开发布作测试。记录验收并提交。
