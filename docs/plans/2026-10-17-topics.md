# 选题中心前端 Implementation Plan

**Goal:** 作为第二个前端页面实现 /topics，并与总控台互通。

**Architecture:** 复用 src/ui 卡片、切换器、按钮、对话框与设计变量；抽取两个页面共同的顶栏。服务器读取配置和选题渠道 Markdown，客户端处理演示数据筛选、选中与跳过。演示选择只保存在当前浏览器的专用 localStorage 键，使用 Zod 校验，保存失败如实提示。

**Tech Stack:** 沿用已有 Next.js、React、TypeScript strict、Tailwind、YAML、Zod，不新增依赖。

## 范围

用户要求继续第二个前端页面，按导航顺序实现选题中心；不跨入数据采集、AI 调用、数据库或第三个页面。继续已确认的先前端开发方式。

## 实施

1. 抽取共享顶栏，使总控台和选题中心可互相导航，其他入口继续禁用。
2. 配置每批数量、探索位范围、FIRE 门槛；创建 config/选题输入渠道.md，内含 Agent 规则、三个内置渠道、外部渠道模板。读取启用状态，UI 不伪报保存了文件。
3. 演示 20 个候选含 3 个探索位，使用 1–2 句方向与示例原始线索；FIRE 必须带 D21 理由。没有真实来源链接时显示 --，不虚构链接。
4. 三栏界面：渠道筛选；搜索、候选/已选/跳过、FIRE/探索筛选与列表；选题详情与已选清单。支持选中、跳过、恢复；第一次选中的 FIRE 状态与理由定格。
5. 完整样本、样本不足、无数据三种演示场景。切场景不改既有定格记录；真实 AI 生成按钮禁用并说明原因。
6. 类型检查、生产构建；Ego 在 1440 / 1728 下截图；验证状态、持久化、空结果、FIRE 门槛与定格、焦点、总控台回归。记录后提交 Git。

## 验收边界

只交付前端交互，不宣称 PRD 第 13 章第 7 步的 AI 推荐功能上线。演示资料、历史表现、热度均不代表真实调研；探索来源线索可检查，但近期热度仍待真实采集验证。
