# 视频发布四项输入 Implementation Plan

**Goal:** 用户只填主题、标签、三种封面、视频路径，选平台后上传，检查平台草稿后单击发布。

**Architecture:** 复用发布页与发布批次，在现有 draft JSON 中添加可选 videoInput；不迁移表、不增加依赖。手填主题自动建立关联作品；在做选题一键带入标题。封面引用已有素材，不更改素材归属。路径在上传阶段才读取。旧批次与非视频流程兼容。

**Tech Stack:** TypeScript、Next.js、SQLite/Drizzle、Vitest、Ego。

## 设计

采用单块四项表单 + 平台选择，移除视频模式的作品选择、成片选择、简介、AI写作、常驻平台配置和重复检查栏。相比仅折叠旧控件，它消除了必须先建作品的额外步骤；相比另建一整套发布中心，它复用现有回执、版本校验和防重逻辑。

主题为发布标题；选题只提供一键填入，不作为必填。三个封面比例从配置读取；可选生图素材或上传本机图片，比例不符就明确提示，不暗中裁图。草稿自动保存，选题来源和素材引用保留在批次。素材改变必须使已有上传审核失效。

上传、平台审核截图、用户点击发布、真实回执是独立阶段。现有 actions 接口仍为 unavailable，不能宣称 skill 的历史实测等于本项目已接通。先完成本地准备，再用用户明确允许的新作品进入真实上传核验；不拿旧作品或真实候选做测试。最终发布仍等待本批审核后的点击。

## 步骤

1. 修改 `src/lib/publishing-model.ts`、`publishing-store.ts`：兼容可选输入、原子建档、全库封面引用、版本与锁定校验；添加临时数据库测试。
2. 添加 `src/ui/video-publish-inputs.tsx` 并在 `src/app/publishing/publishing-page.tsx` 接入四项输入；保留现有非视频流程。
3. 验证保存/刷新恢复、手填/在做选题、封面选择/错误比例、未上传禁止发布；运行 `npm run format`、`npm run check` 与构建。
4. Ego 隔离测试页截图 1440/1728，自查 design.md；提交本步并补 ROADMAP 记录。
5. 用户提供并授权真实新素材后，按 ROADMAP 第11步核验实时平台控件并实现浏览器上传、回执与审核后发布，不使用猜测选择器或空壳成功状态。
