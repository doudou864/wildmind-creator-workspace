# 独立发布任务 Implementation Plan

**Goal:** 每条发布准备独立保存、切换；上传任务可独立暂停/恢复/删除，删除只清理该任务的资源。
**Architecture:** 复用 publish_records 与 collection_state JSON 元数据，任务ID隔离资源和控制意图；不新增依赖或改表。界面不再以当前任务是否运行阻止新建，切换前完成当前自动保存。上传执行端目前未接通，不制造运行中的假任务。
**Tech Stack:** Next.js、TypeScript、SQLite/Drizzle、Vitest、Ego。

1. 明确本地草稿与真实执行状态；固定位置显示上传入口和不能上传原因。
2. 为发布任务持久化暂停/删除意图、资源所有权与恢复点；只终止匹配任务身份的独立进程组，浏览器清理由 src/browser 完成。删除保留源文件、回执、查重记录；清理失败可见且允许重试。
3. 新建与切换先排空保存队列；任务列表各自显示当前状态与可用操作，轮询所有活动任务。当前任务状态不锁住其他草稿。
4. 临时数据库与假执行器验证多任务隔离、暂停/恢复、删除清理、未知提交不重试；Ego 隔离页面验证新建、切换与两档截图。format/check/build后提交、更新ROADMAP。
5. 用户本轮已授权新作品的抖音、小红书、B站、YouTube真实上传验收；继续接通执行端，上传后停在待审。实际上传核验与后台任务自动执行分别记录，不把手动浏览器操作冒充按钮执行完成。
