# U7 · 作品流程合并方案

2026-10-20。**仅方案，等待用户确认后实施。** 本段不改页面代码、导航、接口、数据库或业务规则。

建议把主导航收成「今天 / 消息 / 作品 / 创作」。收起的是找入口的负担：生图、排版、发布仍是各做一件事的独立步骤，素材库和确认稿仍是交接边界。

## 1. 导航方案比较

| 方案 | 入口 | 好处 | 代价 |
|---|---|---|---|
| A 保留 8 个入口 | 现有总控台、数据中心、选题、生图、排版、发布、收件箱、商单 | 熟悉、改动少，可直接进工具 | 开始一条内容时仍要自己记住在哪一页继续 |
| B 推荐：4 个入口 | 今天 / 消息 / 作品 / 创作 | 先看要做什么；围绕作品继续，不反复选作品；消息与商单放同一组 | 需整理页面外壳和深链接；第一次要适应新入口 |
| C 3 个入口 | 今天 / 消息 / 创作（含作品数据） | 主导航最短 | 创作里既做内容又看表现，重点再次混在一起，不推荐 |

推荐 B 的分工：

- **今天**：沿用 U2 今日行动、读取健康、趋势和近期作品。异常仍能直达处理页。
- **消息**：默认值得回复的消息，组内切换消息 / 商单；统计仍共用 inboxSummary，商单状态不另起定义。
- **作品**：查作品、继续制作、看已发布表现。草稿与已发布以现有资料判断展示，不新增数据库生命周期。平台数据仍按平台看；现有数据中心的分析范围保持不变，不借导航合并扩大到未接入平台。
- **创作**：选题 / 素材 / 排版 / 发布检查。一个时刻只展开一个步骤的主区，其他步骤是入口和简短摘要。

旧的八条路径先继续可用，导航只是换分组；保留 message、theme、post、content、topic、layout 等已有参数。以后若增加新的路由外壳，也先做兼容链接，不让已有书签与截图审查入口失效。

## 2. 创作每一步

| 步骤 | 页面主要显示 | 唯一主操作 | 什么时候可跳过 | 带到下一步 |
|---|---|---|---|---|
| 选题 | 候选、理由、来源、未验证热度提示；已有作品则直接继续 | 选中一个方向 / 候选少时生成 | 已有作品或明确内容需求可直接开始 | topicId；首次选中定格仍由原后端处理 |
| 建立作品 | 标题、内容形式；仅在还没有作品时出现 | 创建并继续 | 已有 contentId 时整步跳过 | contentId、topicId、原有内容形式与计划日期 |
| 素材 | 当前作品要求、风格、比例、图片结果与素材库 | 生成图片；已有合适图时采用此版 | 已有合适素材；视频成片来自本机时可只补封面 | 资产 ID、既有选定版本及作品封面引用；视频 ID 不与图片 ID 混用 |
| 排版 | 文章输入；排版后是三份平台版本、配图与预览 | 开始排版 / 完成检查后确认该版本 | 视频作品不需要排版；已有有效确认稿可以直接准备发布 | contentId、layoutId、平台版本；交接使用原有确认稿快照 |
| 发布准备 | 成片或确认稿、平台、平台文案、字数、仅剩未完成项 | 补齐最先缺少的材料；准备好后检查并上传 | 没有可发布内容时可退出，但不能跳过检查 | 原有 draft/batch、快照 ID、所选平台和材料指纹 |
| 上传后审核 | 逐平台实际截图与结果 | 用户核对后确认发布 | 不可跳过 E/F；上传不等于发布 | 原有回执、截图、时间与状态 |

“完成某步”只是一句基于已有记录的界面摘要，不新建进度字段、不自动变更业务状态。任何稿件确认、首次 FIRE 定格、发布准备、上传和最终发布，仍调用各自现有动作。

作品上下文放 URL 的 content 参数，topic/layout 作为已有辅助参数；从作品进入时只选一次。各标签页、浏览器窗口各自保留 URL，不使用一个全局变量抢走另一个窗口的作品。刷新后通过原读取函数恢复；未保存编辑继续使用现有 useEditSession/useAutosave。

多个成片不能自动猜最终版；多个作品档案也不能按标题相似合并。两条 Opus5.5 档案仍分别显示，归并另待批准。

## 3. 复用与工作量

| 现有部分 | 复用方式 | 预计投入 |
|---|---|---|
| WorkspaceHeader、PageHeader、Button、Card、ContentPicker | 新导航外壳；避免步骤内再嵌一套导航和刷新 | 0.5–1 天 |
| Dashboard、InboxPage、DealsPage、DataCenterPage | 分组入口与深链接；继续用 inboxSummary、dashboardRead | 0.5–1 天 |
| TopicsPage、ImagesPage、LayoutsPage、PublishingPage | 提取各页主内容，放进一个作品上下文外壳；步骤只负责自身操作 | 1.5–2 天 |
| 作品清单与继续入口 | 组合现有 contents、草稿与发布读取结果，按明确 ID 关联，不凭名字 | 0.5–1 天 |
| 交接、安全与两档视觉回归 | 多窗口、刷新恢复、不同内容形式、旧路径、过期/未知状态、Ego 实际流程 | 1–1.5 天 |

合计约 **4.5–6.5 个开发工作日**，是在保留现有业务和接口前提下的估计；不包含新增平台能力、数据归并、真实平台首发验收。

继续使用以下接口，不改请求/响应契约：

- `/api/contents` 与作品封面接口；`/api/topics`、生成和单条决定接口。
- `/api/images`、草稿、生成、素材、选版接口；后台生成队列和防重复键继续保留。
- `/api/layouts`、单稿保存和 actions；确认快照仍由原逻辑创建。
- `/api/publishing`、drafts、media、AI、actions、receipts；上传/发布/重试的版本检查和有效性判断原样保留。
- `/api/inbox`、`/api/deals` 和各自既有动作；数据中心继续用现有服务端读取函数。

实施可以分两次提交验收：先换导航和旧路径兼容，再引入作品上下文外壳及步骤切换。每次都保留旧页面可回退，不搬数据库、不批量改状态。不新增依赖。

## 4. 与 PRD 第 5 章第 10 条的关系

原文是“一个板块只做一件事”，并明确素材库交图片、确认稿交图文。推荐方案保持这三条责任边界：

- 素材步骤不会编辑发布文案；排版步骤不会直接写入平台。
- 发布步骤只能消费已经确认的图文快照，不能顺手修改确认稿。
- 同一个“创作”入口负责带路，不能把三个编辑器和发布按钮全部挤到同一页。

因此方案是**导航分组与上下文连续**，不是把职责和状态揉在一起。如果用户希望取消确认稿、在发布页直接改已确认正文、跨平台合并指标或自动跳过上传审核，那是另一个业务需求，必须另外确认。本方案不包含。

## 5. 低保真线框与走查

三个 HTML 无外部依赖，可以直接在浏览器打开；仅演示结构与页面跳转，没有任何平台上传/发布能力。内容为布局示意，不作为数据库验收数据。

1. [作品入口](u7/01-works.html)：从作品卡片继续当前制作；已发布作品有看表现入口的布局位置。
2. [创作 · 素材](u7/02-create.html)：作品留在顶部，步骤切换不要求再选；素材列表与要求处于一个主区。
3. [发布检查](u7/03-review.html)：只有未完成项，缺横版封面则主操作带回素材步骤；上传禁用。
