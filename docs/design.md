# design.md · 前端设计规范

风格：**工业仪器面板**。暖灰底、平面卡片、等宽数字、黑白为主、只用一个橙色做强调。
视觉参考：`docs/design-reference.webp`（总控台）。其他页面没有参考图时，沿用本文件的规则和组件。

## 1. 原则

1. **数据是主角**：大数字、方块、格子条承担信息，装饰越少越好。
2. **只有一个强调色**：橙色只用来标「需要注意」的东西。一屏里橙色越少，越有用。
3. **平面、硬朗**：不用渐变、大阴影、大圆角、毛玻璃；界面里不用 emoji，少用图标。
4. **只做桌面宽屏**：最小宽度 1440px，不做手机适配。

## 2. 颜色（只用这些）

| 变量 | 色值 | 用途 |
|---|---|---|
| `bg` | `#D9D7D3` | 页面背景 |
| `card` | `#EEECE8` | 卡片 |
| `line` | `#BDBBB7` | 卡片边框、按钮边框 |
| `line-soft` | `#CFCDC7` | 行分隔虚线、未点亮的方块和格子 |
| `ink` | `#1A1A1A` | 主文字、点亮的方块、选中态背景 |
| `ink-2` | `#7A7873` | 次要文字（小标签、说明） |
| `ink-3` | `#A3A19C` | 弱文字（坐标轴、`--`） |
| `accent` | `#FF5A1E` | 强调：当前导航、异常、待处理、达到命中阈值、最新一天 |
| `accent-dark` | `#C9400F` | 强调按钮的底边阴影 |

**橙色用在哪里**：当前导航页、健康条的抓取失败、待处理商单数量（大于 0 时）、`HOT` / `DROP` / `FIRE` 标签、倍数达到命中阈值的格子条、趋势图的最新一天、粉丝净减。除此之外一律不用。

### 发布中心 v1.8 的明确例外

按 2026-10-17 的需求变更，发布平台问题卡片用 `warning`（`#E4C66A`）标黄，仅用于需处理的问题卡边线/摘要底色，配黑字及文字原因，不靠颜色单独传达状态。其他页面继续禁止第二强调色。验收第 2 项包含此例外。

## 3. 字体与数字

- 等宽：`"JetBrains Mono", "PingFang SC", monospace`，用于数字、时间、英文代号（`DY`、`00 · SOURCE`、`4 ITEMS`）。
- 正文：`"PingFang SC", -apple-system, sans-serif`，用于中文标题和内容。
- 所有数字开启 `tabular-nums`。

| 层级 | 字号 / 字重 | 示例 |
|---|---|---|
| 主数字 | 44px / 700 等宽 | `128,402` |
| 大数字 | 32px / 700 等宽 | `86,214`、商单 `02` |
| 指标值 | 20px / 600 等宽 | `46,210`、`31.4%` |
| 卡片标题 | 15px / 600 | `今日行动` |
| 正文 | 14px / 500 | 作品标题 |
| 小标签 | 12px / 400，`ink-2` | `D21 基线`、`视频 10-02` |
| 代号 / 表头 | 11px / 500 等宽，全大写，字距 0.08em，`ink-2` | `TITLE`、`4 ITEMS`、`SYNC` |

**数字格式**：千分位 `128,402`；百分比保留 1 位 `31.4%`；倍数保留 1 位：格子条前只写数字 `3.4`，文字说明里写 `3.4×`；空值显示 `--`；时间 `10:41`，昨天写 `-1D 10:38`；日期 `10-02`；顶栏日期 `2026-10-16 FRI`。

## 4. 布局

- 背景 `bg`，卡片间距 12px，卡片内边距 18px。
- 圆角：卡片 6px，按钮 4px，标签 2px。
- 卡片：`card` 底 + 1px `line` 边框，无阴影。
- 列表行之间用 1px 虚线 `line-soft` 分隔，行高约 56px。
- **总控台**：顶栏 → 通栏健康条 → 三栏（左 1/4：今日行动、商单、洞察与异常｜中 1/2：平台趋势、近期作品｜右 1/4：粉丝）。

## 5. 通用组件

| 组件 | 规则 |
|---|---|
| 卡片标题 | 左侧 `01` 编号（11px 等宽，`ink-2`）+ 标题；右侧放元信息（`4 ITEMS`、`LIST →`、`30D`） |
| 导航按钮 | 键帽样式：`card` 底、1px `line` 边框、`box-shadow: 0 2px 0 line`；当前页为 `accent` 底白字，阴影用 `accent-dark` |
| 小按钮 | `送进选题`、`重抓`：12px，1px 边框；`重抓` 用 `ink` 底白字 |
| 切换器 | `7D / 30D / 90D`、平台切换：小描边块，选中为 `ink` 底白字 |
| 标签 | 11px 等宽大写，`accent` 底白字：`HOT`（可能在爆）、`DROP`（下滑或限流）、`FIRE`（🔥 选题）；`EXPLORE`（探索位）用 `ink` 描边 |
| 状态点 | 健康条：◉ 成功（`ink`）、● 失败（`accent`）、○ 尚未抓取（`ink-3`） |
| 字母序号 | 今日行动的 `A B C D`：方框描边，等宽字 |
| 走势类型 | 用文字表示：爆发型 / 长尾型 / 昙花型 / 未命中 / 观察中 / 走势中，不用 emoji |
| 空状态 | 一行 `ink-2` 文字，例如「今天没有待办」 |

## 6. 图表（ECharts，统一主题放在 `src/ui/`）

- **方块柱状图**（平台趋势）：ECharts 象形柱图（pictorialBar），用重复的方块画出每一天。纵向最多 12 格，点亮 `ink`、未点亮 `line-soft`，最新一天用 `accent`。悬停显示当天的准确数值。横轴只标起、中、止三个日期。
- **细针图**（粉丝净增）：柱宽 2px，正值 `ink` 向上，负值 `accent` 向下。横轴标 `-30D` 和 `-1D`，图例写 `净增 / 净减`。
- **格子条**（近期作品的倍数）：用普通网页元素画，不用 ECharts。共 10 格，每格代表的倍数从配置读取（默认 0.35×）；达到命中阈值时点亮色用 `accent`，否则用 `ink`；未点亮用 `line-soft`。
- 所有图表都不画网格线和外框，坐标轴文字用 11px 等宽 `ink-3`。

## 7. 交互

- 悬停：行背景加深一点（`#E6E4DF`），不加阴影。
- 加载中：数字位置显示 `--`，不用转圈动画。
- 动画只用于切换数据时的淡入，时长 150ms 以内。

## 8. 禁止

渐变、彩色阴影、大于 6px 的圆角、第二个强调色、emoji、装饰性插画、居中的大段文字、为了填满版面而加的装饰元素。

## 9. 验收清单（每个页面完成后自查）

1. 用 ego 打开页面，在 1440px 和 1728px 两种宽度下截图，和参考图对照。
2. 颜色是否只用了第 2 节的变量？橙色是否只出现在第 2 节列出的地方？
3. 数字是否都是等宽字体，格式是否符合第 3 节？
4. 卡片、按钮、标签、图表是否复用了 `src/ui/` 里的组件？
5. 空值是否显示 `--`，空状态是否只有一行字？

### 生图等待动效（2026-10-18 用户确认）

生成中的图片框允许一条 ink-2 细线缓慢上下扫描，4 秒单程，不增加强调色；仅后台任务进行时显示，尊重 prefers-reduced-motion。此项是第 7 节动画时长限制的明确例外。

### 数据中心（PRD v1.10）

本条作品曲线允许用 accent 橙色；历史中位线用 ink 深灰虚线，P25–P75 用 line-soft。逐项比较不使用红绿，只用文字结论。

## 10. 可用性规则（2026-10-20 用户确认）

本节是用户批准的可用性改版需求变更，与旧规则冲突时以本节为准。范围只限界面呈现和交互，不改 PRD 的业务口径、算法、采集、数据库结构和接口契约。后续 U 系列步骤不必因为界面与 PRD 原文样式不同停下询问；如果改动会改变业务口径（计数规则、命中率算法、状态定义、分类规则），仍须停下询问用户。

a. 每页只有一个主区域和一个主操作；主操作用 `ink` 实底按钮，在 1440×900 首屏内可见。

b. 能点的和不能点的必须长得不一样：按钮有底色或描边并有悬停态；状态标签（待处理、待回复、待排版等）不加边框，用纯文字或前置小圆点；跳转链接带 →。

b 补充：按钮只用于动词操作。可点击的列表行和条目不加边框，整行可点，悬停背景加深，右侧放 →；需求主题左对齐紧凑排列，超过 8 个折叠并显示“还有 N 个 →”。按钮文字不换行。

c. 页面开头只有一行：页面标题 + 一句现状（如“42 条待回复，1 条商单”）+ 右侧主操作和「刷新」。现状句写“要我做什么”：有待办写待办，没有待办写下一步，不写库存总数。每页只有一个「刷新」，负责整页；作品下拉打开时自动重新读取列表。删除 LOCAL 说明行、英文代号行（如 05 · PUBLISHING DESK）、口号式副标题。

d. 卡片标题不加 00–07 编号，不加英文元信息（BRIEF、ASSET、HANDOFF、WRITE ONCE、READ ONLY 等），只保留有信息量的元信息，如“3 条”“30 天”。

e. 界面里不写规则说明、验收条件、开发进度（审查 A–F、服务未接入、口径解释）。确需解释的用 ⓘ 悬停提示，每页最多 3 个。

f. 没数据就不占地方：整块无数据时折叠成一行，说明为什么没有、什么时候会有；表格某列全空时隐藏该列；图表只画有数据的时间范围。

g. 进入页面时详情面板默认选中第一条，不出现“请选择一项查看详情”的空面板。

h. 同一概念全站同一个词：刷新统一叫「刷新」；作品选择统一用一个组件。

i. 数字全站对得上；口径不同的数字不能用相同或相近的名字。

j. 过期数据要明说：最近成功更新不是今天时，在数据旁写“数据停在 10-17（晚 3 天）”，不能只显示定时窗口。

k. 测试数据只按显式标记（fixture / isFixture / source=fixture / tags 含 fixture）识别，禁止按名称猜。正常页面只在读取层过滤明确标记的数据，不删数据；名称含“验收”“测试”的记录先列入候选清单，由用户逐条确认。

## 11. U9 交互规则（2026-10-20 用户确认）

本节是 U9 原文明确批准的产品规则变更，允许本批次新增所需接口、加法迁移和富文本编辑依赖；不影响第 10 节其他可用性要求。回复判定以 PRD 6.6 的 U9 修订为准，不再沿用“无需手动标记”的旧句。

- 消息处理为「去回复」「不用回（低价值）」「标为已回复」。去回复打开已核实入口、手动归档、复制名字与评论前 20 字；页面底部显示 10 秒撤销，归档页长期提供撤销。平台已确认的回复不因撤销手动标记被伪造为未回复。
- 已归档默认隐藏，不计待回复；同会话明确新对方消息重开并显示「有新消息」。只记录人工低价值，不借此改 AI 分类。直达地址必须实测，无法直达时显示找作品/发送者的提示，私信入口缺失不得编造。

- 成片选择显示白名单文件夹内的最近文件及名称、时长、大小、修改时间，支持绝对路径；不复制原视频。移除、替换、放弃按上传阶段显示，并紧邻说明本地关联与平台文件的区别；已发布只给平台管理链接，未知结果先核实。

- 排版以公众号自由文档为主稿，正文连续编辑，可插图、拖动缩放及撤销重做；平台版本一次展开一个，衍生版写明“和主稿不同步”。主题默认不加，layout-styles.yaml 仍提供可选主题。复制到公众号提供 HTML，实际粘贴限制如实提示；确认后的快照只读。

- 生图默认不加风格，风格预设折叠；画面要求旁可选 1–3 张参考图。作品对话保留原文、原图、原始错误，附加固定说明可展开看原文。超出 2% 自动轻裁的原图弹出人工选区，用户拖框确认后保存，不偷偷改变自动上限。

- 今天页顶部紧凑提示采集失败/超 1 天未更新，明细可展开；新成片只提示，点击才建作品。五类创作记录统一“归档/撤销归档”，提供 10 秒撤销与长期归档入口，不改变历史统计。回复草稿可编辑和复制，绝不自动发送或标记已回复。
