# 2026-10-24 选题角度与 Astra 分工验收

用户反馈：实体有价值，但标题被报价规格、工资和重复次数带偏；第一轮应从普通人的广泛需求或强烈好奇出发。用户指定写选题使用 GPT-6 Astra，其余可用 GPT-6 Sol。

## 已核对的问题与修改

- 只读核对真实候选：电商修图的 direction 确实是“具体服务商品如何标价与拆分规格”；家务采集是“新职业的真实劳动条件”。不是仅句子措辞偏弱。
- 机器人线索提取摘要还夹有“可追问新职业为何仍像流水线”，过早替编辑选角度。现在提取只整理事实、需求、用途及报酬机制；编辑不继承摘要中的建议。
- 在判断调用入口显式传入 topicEditorial 用途，起草与复核读取 config/ai.yaml 的 topicEditorialModel=gpt-6-astra；提取和研究规划继续默认 gpt-6-sol。没有依靠提示词标签路由，不设降级路径；既有 medium 思考强度保持不变。
- 编辑先比较实体的观看理由，把价格/工资等支撑细节与主角度分开。事实约束标题承诺，不强迫把标题写成核查摘要。重写后同时保存最终角度、利益/好奇与兑现内容，避免详情仍停留在旧理由。

## 实际验证

- `npm run format` 与完整 `npm run check` 通过：80 个测试文件、213 项测试，以及全部业务检查。测试覆盖指定模型传入 SDK、Astra 失败不降级、网页伪造标签不能切换模型、生产起草/复核均传指定用途，以及编辑改角度后同步详情。
- `node --experimental-strip-types scripts/verify-topic-workflow-ai.mjs --run-model --angle-regression` 成功。输入为只读复制的两条已有资料，存于 [inputs.json](inputs.json)；只写临时 SQLite，结束后删除，无浏览器采集、无原候选修改。
- 两次真实 CodexJudgment 调用均显式请求 gpt-6-astra，起草 2 条、编辑保留 2 条。完整结构化输出见 [model-fixture.json](model-fixture.json)。requestedModel 记录调用配置，不是通过模型自述鉴定身份。
- 输出：① 会用AI修图还能做什么生意？已经有店铺替商家修商品图、搭场景了。② 叠衣服也能成为有工资的工作？已经有人靠采集家务动作，给机器人当“老师”了。
