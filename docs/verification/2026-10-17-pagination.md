# 第 3 步补修：分页与容量提醒

实现：B站从真实稿件选择框读取近期名单，按每批最多10条导出，并逐批核对CSV的标题、发布时间、条数与来源文件；小红书逐页读取，翻页后回到顶部，在所属页打开到期详情；YouTube的视频与Shorts分别逐页核对总量，报表使用真实滚动容器。重复页、总数变化、缺行会明确失败，不写入不完整批次。YouTube CSV 仍为待办。

容量：config/collection.yaml 的 capacity.warnAt=80、maxRecentWorks=100、maxPages=100，可按实际工作量调整。上述三平台近期作品达到80条时，在 data:show 和“需要你处理”中提示；超过100条停止，不静默截断。提醒不会覆盖登录/风控，不阻塞定时采集，采集成功不会误清；数量回落才解除。数据库复用既有 TEXT kind 字段，无DDL或删改历史数据。

自动测试覆盖：11/23条跨批、末批保留、旧稿排除、CSV分批来源；多页总量、重复页、缺页、总数变化；提醒与登录共存、达到阈值、超过上限、成功后仍提醒、回落解除。

本轮没有复用同日截图、没有需要处理项。五平台合计仍为25条作品，起号日前作品0条，数据库完整性检查ok；采集后自动备份成功。运行ID及原始CSV、截图、JSON路径存于 data/verification/pagination-1017/results.json，三个 data:show 输出与检查日志在同目录。

限制：真实账号目前各只有5条近期作品，小红书/YouTube没有第二页；跨页/11条近期稿件由自动测试验证，没有宣称真实采过不存在的作品。B站真实选择框已核对可取消旧选择并选择默认10条之外的稿件，正式运行仍只记录近期5条。连续3天观察仍未完成；YouTube CSV保持待办。
