# U9 E：后台采集、回复草稿、归档与新成片

后台采集保留原来的时间窗口和重试规则，补齐安装预览、卸载脚本、失败/超 24 小时未更新的系统通知；通知去重，今天页顶部也提示。新成片由白名单目录读取，未关联才提示，用户点击后先核对文件，再一次事务建立作品和路径关联。

值得回复的消息详情增加 AI 回复草稿、可编辑和复制；不发到平台，也不改变回复状态。作品、排版草稿、生图草稿、素材、选题共用归档/撤销入口。归档写独立台账，默认列表收起，原数据、首次定格、确认快照、基线和命中率算法均不修改。10 秒快捷撤销，之后仍可从顶栏“已归档”恢复。

## 验证与四问

- 临时 fixture 数据库覆盖五种记录归档/撤销；归档前后原表逐字段相同，选题首次定格保留，只有展示元信息变化。没有归档真实记录。
- 采集健康测试覆盖 24 小时边界、失败原因与重复通知去重，系统通知发送器用替身，未弹真实系统通知。
- 回复草稿使用现有 Judgment 调用层的测试替身，原消息与处理动作表不变。
- Ego 隔离组件页：归档作品→10 秒内撤销；归档素材→进入已归档→撤销归档；写回复草稿→复制；新成片点击后生成正确创作目标。所有请求、剪贴板和导航为内存 fixture 替身，未新建真实作品或修改真实消息。
- 今天页另用本机真实页面只读截图，看到当前失败/过期提示。成片目录尚为空，真实新文件提示不能验收。
- `npm run collect:install -- --dry-run` 生成预览 plist，`plutil` 检查通过；卸载 dry-run 仅列出操作。未安装、未卸载、未手动触发真实采集。
- 加法迁移 0016 前备份到 `data/backups/u9-e/`；重启服务后 API HTTP 200。`npm run format` 和 `npm run check` 通过，52 个测试文件、116 项测试及原有检查全绿。

| 四问 | 结果 |
|---|---|
| 3 秒内看出最重要的事 | 今天页顶部简短提示采集待处理，详情折叠；新成片有明确建作品入口，原今日行动仍是主区域。 |
| 能点和不能点 | 归档、恢复、复制都是按钮；已归档入口带箭头；等待状态禁用并说明原因。 |

| 数字能否对上 | 采集提醒按平台去重展示；归档不写原业务记录，历史统计仍使用原始数据。测试验证数据不变，未归档真实作品来验证。 |

## 还要你本机验证

安装命令：在项目目录执行 `npm run collect:install`。卸载用 `npm run collect:uninstall`。[完整说明](launchd.md) 包含状态、日志、通知权限与睡眠限制。只有在你安装后看到计划运行和系统通知，才算后台实机验收完成。

还未验证：真实平台采集后的通知、真实目录的新成片、真实 AI 回复质量和系统剪贴板。成片文件夹需在 `config/media.yaml` 的 `finishedVideoDirectories` 填绝对路径；未配置时不擅自扫描其他目录。历史归档的统计保留通过代码与 fixture 验证，没有用真实作品试归档。

最终联检同时修正：对话出图或人工裁剪保存后自动切到右侧素材库；富文档 AI 修改后由文档同步兼容段落，避免预览和确认内容不一致，已有快照测试补入这一断言。
