# U9 A · 手动回复与归档

按已批准规则修订有效 PRD 6.6 和 design 第 11 节。先在线备份，Drizzle 0012/0013 新增处理事件表与显式消息 fixture 标记；不覆盖原消息。服务重启后 /api/inbox 返回 200，真实库仍为 387 条消息、0 条手动处理事件。

## 已实现

每条选中消息提供去回复、不用回（低价值）、标为已回复。去回复在用户点击内先打开页面，再保存已回复/归档，最后复制名字与 Unicode 字符前 20 字；弹窗被拦则不归档，保存失败有错误，复制失败不会误报复制成功。底部 10 秒撤销，已归档列表长期可撤销手动标记。新操作会使旧撤销失效，防止覆盖后来处理或新采集。

总控台/收件箱共用 assessReplies、waitingCount。归档覆盖优先；无覆盖时保留原完整证据判断。归档后同一会话明确新对方消息重开；只有重抓时间变了、历史补读或互动数变化不会重开。缺少可信时间不推断新消息。撤销仅撤手动覆盖，平台已明确回复的消息仍为已回复。

## 四问自查

| 问题 | 结论 |
|---|---|
| 3 秒能否找到要做什么 | 通过：选中消息旁三个处理动作，归档独立入口 |
| 能点与不能点是否可分 | 通过：动作按钮，回复状态纯文字；缺入口/保存中明确禁用原因 |
| 有无无关或难懂文字 | 新功能无内部字段名，回退入口只提示作品和人；技术判断留在本文 |
| 数字是否一致 | fixture 待回复 1→0→1；归档 0→1→0；使用与总控台相同的统计函数，低价值也不会出现在默认可送选题数量里 |

## 低价值记录以后怎么用

先积累人工标记与原分类的差异，只生成供审核的样本清单，区分具体求助、普通寒暄、已经处理等原因；用户确认后再离线比较候选分类规则的误杀率，保留原标签和可回滚版本。未经批准不进入提示词、不自动重分类，不按名字或关键词扩散。
