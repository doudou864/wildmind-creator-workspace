# U9 D：参考图、作品对话与人工裁剪

默认“不加风格”，预设收在折叠设置。可上传或从素材库选择最多 3 张参考图；生成和修改都传入原图，修改时另带原图。每条作品保存独立 Codex thread、原始输入、参考图 ID、原始输出和错误；固定说明可展开。对话返回的图片自动入素材库并关联当前作品。

超出 2% 自动轻裁限制时，原图保留到待裁剪区，弹出固定比例选框；可拖动选区并调整大小。保存时再次验证边界和精确比例，记录原图、坐标、尺寸和 manual 标记，保存后可用作封面。没有放宽自动上限。

## 已验证

- **真实本机 Codex SDK**：临时数据库、显式 fixture 作品，两轮文字对话成功，第二轮复用同一 thread 并正确记得上一轮短语。每轮计 1 次，耗时分别 15521/15473 ms。见 [live-chat-proof.json](live-chat-proof.json)。没有新建真实作品，没有实际生成图片。
- Vitest：用户前后空格和换行原样传递；流式输出；会话复用；重复请求不重复调用；原始 SDK 错误保留；达到每日上限不调用。测试替身不会消耗套餐。
- 人工裁剪：临时 fixture 图片 470×400，自动裁为 2.35:1 被 2% 上限拒绝后进入待裁剪；真实 sips 保存为 470×200，原图仍是 470×400，人工坐标写入记录，重复保存返回同一素材。
- Ego：拖选测试图后实际提交 `{x:0,y:73,width:470,height:200}`；对话输入 `  测试原文\n保留空格  ` 原样发出。隔离页面复用真实组件，网络和图片为内存/SVG fixture 替身，没有真实数据库写入。
- 加法迁移前已备份 `data/backups/u9-d/`，迁移 0015；服务重启后 `/images` HTTP 200。`npm run format`、`npm run check` 通过，49 个测试文件、113 项测试及原有检查全绿。

## 四问

| 问题 | 结果 |
|---|---|
| 3 秒内知道做什么 | 画面要求和生成按钮在左侧；生成按钮在 1440×900 首屏内；待裁剪卡直接说明下一步。 |
| 可点和不可点 | 按钮有底/描边，禁用变淡；裁剪框边缘强调、可拖动；预设收起，不与生成争主操作。 |
| 无关文字 | 用户只看原文对话、必要错误、参考图和人工裁剪提示；系统说明可展开，不混进用户的话。 |
| 数字一致 | 参考图计数取选中 ID；每轮对话共用生图每日上限并记耗时；测试素材未进入真实作品统计。 |

## 未验证与已知问题

真实模型生成/修改图片并自动收取、本机浏览器上传参考图的完整链路本轮未实测；已实测的是 SDK 文字会话、真实裁剪程序和 fixture 组件/数据库行为。实际生成质量、模型是否严格遵循参考图仍需用测试作品验收。对话轮次无论文字或生图都计一次，附加说明要求每轮至多调用一次 image_gen，不自动重试。应用被强制终止时，running 历史保留，需要核对本机会话；不会把中断当成功。
