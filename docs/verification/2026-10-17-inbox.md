# 互动收件箱前端验收 · 2026-10-17

范围：PRD 6.6 与第13章第6步中的互动收件箱前端。继续执行用户“暂不安装依赖，只做前端与服务接口，未接入操作不可用”的决定。商单列表页面留待下一板块。

## 已实现

- `/inbox`：读取状态、平台/评论私信/回复/识别状态筛选、三分类、搜索、分页、需求主题来源、原文、上下文、分类与回复证据。
- 私信按平台+会话计待回复，同一会话较新的读取证据覆盖旧消息；评论完整读取且没有我方回复才为待回复。证据缺失或冲突显示待核对，没有手工标已回复。
- 商单自动流转状态展示；问题与观点同步入口、已同步状态与重复点击保护；其他消息不自动回复。分类失败与待识别均保留原消息，不归入其他。
- `GET /api/inbox` 与 `POST /api/inbox/:id/topic`，后者校验修订号，拒绝夹带手工分类或回复状态。实际同步服务未接入，合法请求503，页面禁用按钮。
- 刷新仅重读本机已存记录，不触发平台抓取。没有平台回复、删除、额外抓取端点。

## 验收结果

- 类型检查、生产构建通过，生成 `/inbox` 及两条接口路由。
- 新增21项收件箱业务断言通过；已有业务21项、排版15项、发布19项全部通过，共76项。使用现有 Node 原生断言，未安装 Vitest 或其他依赖。Node 的模块类型提示不影响通过结果。
- HTTP 6项检查通过：真实空业务读取200，合法同步503，无版本/负修订号/夹带状态或分类400。结果见 `inbox/http-checks.json`。
- Ego TaskSpace 12，14项页面与状态检查通过，结果见 `inbox/browser-checks.json`。覆盖会话去重、原文与上下文、主题追溯、分类失败筛选、普通称赞分类、搜索、平台筛选、商单关联状态、已同步禁用、真实503失败保留原文、下次读取后更新待回复。
- 页面状态测试只在隔离浏览器页替换 GET 返回值；POST 调用真实503接口，没有成功写入样例、平台操作或数据库写入。结束后重新加载页面，测试数据移除，正式页面仍无消息，能力关闭。
- 1440/1728 的空状态及有记录状态截图均检查，无横向溢出。暖灰底、描边卡片、黑色选中态、当前导航和读取失败用橙色；共享组件与设计变量复用。截图位于 `inbox/`；有记录截图明确标为隔离验收数据。

测试过程中一次按钮名称与消息正文重名导致定位歧义，改用分类区域定位后继续通过；一次截图子树参数格式错误不涉及页面代码或业务操作，已改用页面状态检查。没有将这些工具定位问题误报为产品缺陷。
