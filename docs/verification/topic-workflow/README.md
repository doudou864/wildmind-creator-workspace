# 选题发现与观看角度工作流验收 · 2026-10-23

## 已实现

- 现有“生成20个候选”入口沿用后台worker，接入来源观察、主动搜索、真实链接追读、实体/角度草稿和独立编辑复核。
- `config/topic-workflow.yaml` 保存用户确认的角度规则和正反例、研究预算、网页/淘宝站内搜索入口；不新增依赖或数据库表。
- 抖音搜索关键词、看后搜和主动同步的问题一直参与，按渠道及页面分配材料预算，不再被新外站内容排除。读取源日期保留。
- 草稿要求实体、不同观看理由、利益/强烈好奇、内容兑现和原文引用；编辑独立判断兴趣、事实支持、重复，代码校验引用和预算。同实体最多两个不同角度，探索配额不再导致整批拒收，FIRE计算/首次冻结保持原规则。
- 固定来源可滚动浏览；搜索页只提供链接，不作事实证据。所有新增链接来自页面DOM，查询URL来自配置。两轮规划、最多6组查询/16个详情链接；初轮为搜索结果预留正文预算。每页3屏、24000字符，超过保留已有原文。登录、网络失败单独报告并继续，用户接管立即停。
- 生成阶段刷新可恢复；首轮仅显示句子和想看/无感，点击才展开依据。最后一条被跳过后仍可切换到已跳过并恢复候选。
- 保留用户未提交的三个来源条目和既有ROADMAP播放图记录，不改变真实候选、消息或作品。

## 验证

- 全量 `npm run check`：72个测试文件、178项测试，以及项目原有业务检查；格式、类型检查通过。正式构建通过。
- 临时数据库集成：固定来源→模型规划搜索词→搜索摘要→追正文→同时带入search/after_search→草稿→编辑→保存，逐站状态与来源URL可回溯；搜索摘要里的夸张收益不进入生成材料。
- 故障/边界：单站登录/网络失败继续、无材料不生成、复核失败不入库、旧选择保留、无原文/虚构引用排除、同实体同角度去重、不同网页公平分配、查询/详情预算、禁用来源、任务防重与进程失活。新模型协议递归检查全部字段必填。
- 真实本机Codex模型只用4段明确标记的虚构测试资料跑草稿和编辑两次调用；目标6，最终4条。返回值全部通过新Zod协议并在临时库入库，随后清理临时库。记录见 [model-fixture.json](model-fixture.json)，内容不得发布或视为真实商业机会。复验命令 `node --experimental-strip-types scripts/verify-topic-workflow-ai.mjs --run-model` 会消耗模型额度，非自动测试的一部分。
- Ego隔离页面：点击生成、运行中禁用按钮、刷新恢复任务、切到复核阶段、完成自动更新、默认无依据、点击展开依据、无感→已跳过→移回候选→想看。前端接口全部由fixture接管，没有写真实库。
- 实机只读：Bing搜索结果与淘宝站内搜索URL已打开核对；工作台 `/topics` 返回HTTP 200，实际页面读取到3个现有外部渠道，生成按钮可用、默认无详情、1728宽无溢出。没有点击真实生成按钮。

## 实测边界

真实模型测试证明新协议和两阶段调用能工作，不代表真实各平台整轮采集已经完成，也不证明每条句子都能打动用户或取得流量。真实网站可能有登录、风控、无链接或无正文限制，将明确显示；不足20保留合格结果，全部不合格则不伪造。下一次用户点击生成才运行真实研究批次，并用实际想看/无感与发布记录持续校准。

当前网页仍显示此前任务的失败明细与旧候选，属于历史记录，未伪装成新版采集结果。Ego提示可更新，本次未升级。
