## 1. 项目背景与目标

### 1.1 背景

「野生脑洞」是一家一人公司（OPC），收入主要来自自媒体账号运营，**抖音是主要变现渠道**。账号同时在 9 个平台运营，数据分散在各平台的创作者后台里，商单线索散落在各平台的评论区和私信中。需要一个自建的工作台，集中完成数据监控，并实现部分自动化。

### 1.2 目标

> 集中完成**选题发现、内容分发、数据复盘和商单提醒**，让用户**每天早上几分钟内看清楚今天该做什么**。

### 1.3 第一性原理

```
收入 ≈ 产出作品数 × 单条作品的注意力 × 注意力变现率（商单 + 其他）
```

- **数据本身就是指导新媒体运营的核心价值之一。** 工作台的数据设计原则是：每一块数据都要能回答一个具体问题，帮助做出一个具体决策。
- 用户在非创作环节花的时间不多，所以本项目的重心**不是"省时间"**，而是**提升"选题 → 发布 → 数据 → 再选题"这个闭环的质量**。

### 1.4 成功标准

| 维度 | 标准 |
|---|---|
| 主观 | 用户本人的实际使用体验 |
| 客观 | ① **抖音 D21 基线持续上升**（最近 20 条作品第 21 天播放的中位数，代表整体水平；视频、图文各看各的）；② **🔥 选题的命中率高于非 🔥 选题**（AI 判断有效） |

> 命中率衡量的是「相对自己最近的水平」：整体变强时基线会跟着涨，命中率不会随之提升，所以它不适合当「有没有进步」的标准，只用来判断单条作品和选题（见第 7 章）。

## 2. 范围：做什么、不做什么

### 2.1 本期范围 ✅

| 模块 | 一句话说明 |
|---|---|
| 数据中心 | 单条抖音作品同龄对比、逐项诊断与按需 AI 解读，详见第15章 |
| 总控台 | 每日晨报：数据健康、今日行动、分平台趋势、粉丝、作品表现、洞察与异常 |
| 选题中心 | 读取可编辑的渠道文档 → AI 提炼方向 → 20 个候选 → 用户筛选；🔥 标记高潜力选题 |
| 生图中心 | 所有图片都在这里做：视频封面、公众号封面、文章插图、抖音图文配图、自由生图；统一存进素材库 |
| 排版中心 | 图文的排版、修改、预览：一份文章出公众号版、抖音图文版、X 版；“确认并送去发布”一次完成 |
| 发布中心 | 只管发：视频上传 + 接收排版中心确认稿 + 发布模板 + 一键确认分发；图片从素材库取 |
| 互动收件箱 | 只读，汇总评论与私信，由 AI 分类 |
| 商单列表 | 记录商单线索，三种状态 |
| 复盘引擎 | 同龄基线对比、走势分类、选题命中率 |
| 数据底座 | 浏览器采集（按平台用截图 + AI 视觉或导出文件）、指标字典、每日快照 |

### 2.2 明确不做 ✅

| 不做 | 原因 |
|---|---|
| 脚本撰写 | 用户已有自己的平台和笔记软件 |
| 拍摄 | 工作台无法介入 |
| 剪辑、包装 | 在其他平台完成，放进工作台反而不方便 |
| 评论、私信自动回复（包括普通称赞） | 用户自己会看私信；保持账号的人味；降低账号风险 |
| 跨平台作品对比 | 同一条作品在不同平台之间对比没有意义，**只和本平台的历史作品比** |
| 平台 API | 平台数据管控严格，API 拿不到数据。导出文件是否使用**按平台标注**（见第 3 章「采集方式」列） |
| 复杂的商单流程 | 极简原则，三种状态够用 |
| 使用 Notion 搭建 | 直接自建独立的工作台 |

|---|---|---|---|---|---|
| **抖音** | 短视频 + **图文** | **主阵地、主要变现渠道、选题判断的依据** | ✅ 播放量 | 截图 | ✅ 已定稿 |

| 快手 | 短视频 | 跟随分发（**尚未发布**） | ❌ | 🟡 默认截图，首发后确认 | 🟡 框架 |

| X | 图文 | 跟随分发（海外，**尚未发布**） | ❌ | 🟡 默认截图，首发后确认 | 🟡 框架 |

**各平台的复盘主指标**（总控台第 4 层的 D3 / D7 / D21 倍数和走势类型用它计算；只有抖音和公众号计入命中率）：

| 平台 | 复盘主指标 |
|---|---|
| 抖音（视频 + 图文） | 播放量（含扶持流量） |
| 公众号 | 阅读人数 |
| 小红书 | 观看数 |
| B 站 | 播放量 |
| YouTube | 观看次数 |
| 视频号（视频） | 播放量 |
| 视频号（图文） | 曝光量 |
| 快手、TikTok | 播放量 |
| X | 曝光 |

**采集方式按平台固定标注**：每个平台在处理指标字典时定下用截图还是导出，写死在配置里，采集程序直接按标注执行，不做运行时判断。

## 5. 设计原则 ✅

1. **极简。** 够用就行。不为了流程而流程，不让维护状态、填写字段消耗精力。
2. **每块数据都回答一个决策问题。** 回答不了的就不展示、不采集。
3. **按平台看，只和自己比。** 各平台的量级和口径完全不同，不做跨平台对比，每条作品只和**本平台的历史作品**比。
4. **同龄对比。** 新作品与历史作品必须比较**发布后同一天数**的数据。
5. **实际表现是复盘的唯一标准。** 用户的偏好只决定"推什么"，不参与复盘打分。
6. **只读优先。** 平台写操作仅限用户触发的发布流程：上传/保存草稿与最终发布分开，最终发布必须再次由用户一键确认。
7. **数据时效透明。** 每个平台都显示"数据更新时间"，抓取失败必须提示。
8. **以抖音为准。** 选题判断、命中率核算优先基于抖音；公众号开始运营后单独算一个命中率，不和抖音合并。
9. **单人本机默认自动保存。** 普通选题状态、生图草稿、排版编辑、作品信息以最后保存为准，只保留 updatedAt，删除 expectedRevision、409 冲突提示及未保存离开提醒。仅发布执行（上传、全部发布、重试）以及后台可能并发修改的消息、商单、选题生成结果保留版本检查和防重复；后台生成不得覆盖用户选择和首次定格。
10. **一个板块只做一件事。** 生图中心只管出图，排版中心只管排版，发布中心只管发；图片通过素材库交接，图文通过「确认稿」交接。

## 6. 功能模块详述

### 6.1 总控台

**使用场景：** 用户每天 **11:00 之后**看一次（此时当天抓取和重试都已完成）。数据每天 10:32–10:45 更新一次，所以总控台是"日报"节奏，而不是实时大屏。

#### 6.1.0 顶栏：数据健康条（常驻）✅

每个平台一个小标签，显示：

| 状态 | 显示内容 |
|---|---|
| ✅ 今日抓取成功 | `数据更新时间：今天 10:41` |
| ⏳ 今日尚未抓取 | `数据更新时间：昨天 10:38`（显示最近一次成功抓取的时间） |
| ❌ 今日抓取失败 | `数据更新时间：昨天 10:38`，标红，写明失败原因（比如"抖音登录失效，请重新扫码"），旁边放一个 **[立即重抓]** 按钮 |

规则：**"数据更新时间"始终显示最近一次成功抓取的时间。** 今天成功了就显示今天，没成功就显示上一次。

#### 6.1.1 第 1 层：今日行动（只在有事时出现）✅

- 按类型汇总数量并链接至筛选后的处理列表：首页不展开逐条原文、品牌或等待时长。商单和私信按会话去重，评论按条计数。
- 有价值的评论或私信待回复；仅确认未回复才计入，回复记录不完整时单列待核对；送入选题不等于已回复。
- 计划今天发布的内容（作品上填了「计划发布日期」的）
- 需要手动处理的异常，比如登录失效

没有待办时只显示一行"今天没有待办"，然后直接进入数据区。

#### 6.1.2 第 2 层：平台趋势 ✅

- **切换方式：按平台切换**（抖音、小红书、B 站……）
- 每个平台显示**自己指标字典里的核心指标**的日趋势，不强行统一口径
- 时间范围：7 天、30 天、90 天

#### 6.1.3 第 3 层：粉丝 ✅

分平台查看，每个平台一张组合图，展示两个维度：
- **折线：粉丝总数的变化**
- **柱状：每日粉丝净增数的变化**，净增为负的日子标红
- 如果平台分别提供新增和取关，鼠标悬停时拆开显示

#### 6.1.4 第 4 层：近期作品与商单 ✅

- **作品表现（按平台）**：近 30 天的每条作品显示以下内容，倍数越高颜色越深
  - 发布后第 3、7、21 天各自相对于同龄基线的倍数，例如 `D3 2.1× ｜ D7 1.6× ｜ D21 1.8×`
  - 当前状态：观察中 / 早期强势 / 早期平淡 / 走势中 / 已终判
  - 已终判的作品显示走势类型：🚀 爆发型、🌱 长尾型、🎆 昙花型、未命中
- **商单**：三种状态各自的数量，加上商单列表的入口

#### 6.1.5 第 5 层：洞察与异常 ✅

- **需求主题**：从互动收件箱里"有价值的问题"归类出的高频主题，列出前几名，每条都能一键送进选题中心
- **作品数据异常**：在 D1、D3 检查点，作品表现超过同龄基线 3 倍（可能在爆，需要跟进），或低于 0.3 倍（可能被限流）。D1 只用于异常提醒，不参与走势分类
- **账号异常**：违规通知、限流提示、粉丝异常下降

### 6.2 选题中心

#### 6.2.1 流程 ✅

```
多渠道输入 → AI 提炼成 1–2 句选题方向（附信息来源）→ 一次给出 20 个候选 → 用户凭直觉筛选 → 进入制作
```

#### 6.2.2 输入渠道 ✅

输入渠道做成一份**用户随时可以修改的文档**（`选题输入渠道.md`，也可以封装成一个 Agent skill）。选题 Agent 每次生成候选前先读这份文档，按里面启用的渠道去读内容。**增删渠道只改文档，不改代码。**

文档分三部分：
1. **Agent 读取规则**：只读启用的渠道；每条线索提炼成 1–2 句方向并附来源；20 个候选含 2–3 个探索位
2. **系统内置渠道**（工作台自动提供，只能开关）：见下表
3. **外部渠道**（用户自己增删）：每个渠道写名称、启用、类型、位置、关注什么、读取频率、备注

**系统内置渠道：**

| 输入源 | 说明 |
|---|---|
| 抖音「搜索关键词」 | 用户通过哪些词搜到了你的作品，属于**主动需求** |
| 抖音「看完作品后常搜的词」 | 观众看完还想知道什么，**可以直接作为下一期选题**。例如 `gpt6.1sol和astra对比`、`kyc` |
| 互动收件箱中"有价值的问题和观点" | 一键同步过来 |

**不采用：** 小红书「笔记灵感」（选题以抖音为准）、YouTube「热门趋势」灵感页。

#### 6.2.3 推荐逻辑 ✅

> **偏好决定"推什么"，表现决定"标什么"。**

| 信号 | 来源 | 作用 |
|---|---|---|
| 偏好 | **用户做过的历史选题**（做过的选题就是用户真实的偏好） | 决定 20 个候选的方向范围 |
| 实际表现 | 抖音、公众号的复盘数据 | 决定哪些候选打上 🔥 |

- **不设权重，也不把两个信号合成一个分数。** 两个信号各管一件事。
- **🔥 高亮**：AI 根据历史表现数据推断某个候选更可能火。「同类题材」由 AI 按语义直接判断，**不维护标签**。每个 🔥 **必须附一句理由**，注明 D21 倍数，有走势类型时一并注明，例如：
  > 🔥 同类"XX"题材你做过 3 条，其中 2 条是 🌱 长尾型，第 21 天平均是基线的 2.3 倍
- **🔥 开启门槛**：累计 **20 条有 D21 结果的抖音作品**（含历史导入的补录）后才开启。在那之前只推荐，不高亮。
- 🔥 标记在用户选中选题时定格，之后不再改动，用于 7.4 的 🔥 / 非 🔥 对比。
- **探索位**：20 个候选中留 **2–3 个**给"你没做过、但近期热度高"的方向，单独标为「探索」，用来防止信息茧房。

### 6.3 生图中心 ✅

**定位：** 工作台里所有图片都在这里做。需要什么图就来这里生成，生成好的图放进素材库，排版中心和发布中心直接取用。**生图中心只出图，不发布。**

```
选用途 → （可选）关联选题或作品 → AI 按主题和内容生成 → （可选）通过聊天框修改 → 选定一版（关联作品即采用，未关联则为素材库默认） → 排版中心 / 发布中心取用
```

| 用途 | 规则 |
|---|---|
| 视频封面 | 每条视频固定生成 **3:4、4:3、16:9** 三张；生成时 AI 自动参考对应比例点击率最高的几张历史封面（3:4 看小红书，16:9 看 YouTube，横版也参考 B 站星级），用户无需操作 |
| 公众号封面 | 同时生成 **头图 2.35:1 和转发卡片 1:1** |
| 文章插图 | 按文章段落生成；用户已有的图优先，不够时再生成 |
| 抖音图文配图 | 和公众号是同一份内容，按抖音竖版比例重新出图（默认 3:4，可配置） |
| 自由生图 | 不限用途，自己写需求 |
| 上传 | 自己手动做的图（比如小红书图文）也上传进素材库，统一管理 |

| 项目 | 规则 |
|---|---|
| 素材库 | 每张图记录用途、比例、关联的选题或作品、来源（AI 生成 / 用户上传）、提示词；同一张图可以改出多版，选定一版给发布中心用 |
| 聊天框 | 用自然语言改图（换文字、换配色、换构图等） |
| 风格 | 封面风格、插图风格、各用途的默认比例都写在配置文件里（11.2） |

生图草稿和素材信息自动保存；选定时有作品就同步采用，无作品只设置素材库默认版本，不再分成“选定”和“作品采用”两步。

### 6.4 排版中心 ✅

**定位：** 图文的排版、修改、预览都在这里做。使用一个“确认并送去发布”按钮，只弹一次确认框，确认后送去分发。排版中心不发布。

```
粘贴文章 → 识别结构（标题 / 小标题 / 正文 / 引用 / 列表）
        → 公众号自由文档主稿（可选主题，默认不加主题）
        → 素材库选图或直接上传，拖动调整图片大小
        → 从公众号主稿一键生成抖音图文版、X 版，之后独立编辑
        → 展示、修改、预览
        → 确认并送去发布（只弹一次确认框）
```

#### 6.4.1 输出版本 ✅

| 版本 | 说明 |
|---|---|
| 公众号版 | 完整样式；封面用素材库里的 2.35:1 + 1:1 |
| 抖音图文版 | 和公众号**通用同一份内容**，见 6.4.3 |
| X 版 | 同一份结构，**去掉样式**（X 长文只支持标题、加粗、列表、图片） |

#### 6.4.2 修改、预览与确认 ✅

| 项目 | 规则 |
|---|---|
| 展示 | 公众号主稿使用自由文档编辑区；平台标签一次展示一个版本；其他平台标明“和主稿不同步” |
| 修改 | 可以直接改文字，也可以用聊天框让 AI 改（改标题、精简段落、调顺序、换配图等）；**三个版本各改各的，不自动同步**（三版只在第一次生成时来自同一份文章） |
| 换图 | 从素材库选或上传图片，可拖动缩放；正文支持撤销、重做，无固定段落格子 |
| 预览 | 按各平台的真实效果预览（公众号手机端、抖音图文左右滑、X 长文） |
| 确认并送去发布 | 每个平台版本一个按钮，只弹一次确认框，确认与交接原子完成；已送出版本保留“退回修改”。发布中心只分发，不改正文 |

U9 补充：旧段落无损转换为富文档，保留文字、图片引用及说明；旧确认快照不回写，新的确认稿冻结完整文档。复制到公众号输出带样式 HTML；平台粘贴兼容性以实测为准，本机图片可能需在公众号重新上传。

#### 6.4.3 抖音图文 ✅

抖音图文和公众号图文**通用**，不单独做产线：文字复用公众号版，再按抖音的习惯精简成图文文案；配图由生图中心按抖音竖版比例出（默认 3:4）。张数上限等按抖音常规值做默认，写进配置文件，可改。

**和视频的联动：** 图文是低成本试选题的方式。图文反响好的选题，可以优化成视频（同选题同内容或类似内容）。

### 6.5 发布中心

**定位：** 只管发。视频从这里上传；图文接收排版中心确认过的版本。**发布中心不生图、不排版**，套用各平台的发布模板后，用户一键确认分发。

#### 6.5.1 视频发布 ✅

```
选作品、选成片 → 只带出所选平台需要的封面 → 填一次通用文案 → 选平台并自动生成版本
→ 上传到各平台（不点击发布）→ 查看各平台填好后的截图 → 用户确认一次「全部发布」→ 逐平台回执
```

1. **内容来源**：选择作品后，只允许从 config/media.yaml 的成片文件夹白名单读取 MP4/MOV；列出最新文件的名称、时长、大小和修改时间，也支持粘贴白名单内的绝对路径。新成片只保存原路径及大小、修改时间、SHA-256 指纹，不复制到 data/videos；上传前重新校验，变化或缺失须重新选择。旧副本保留。未上传可移除关联或替换；已上传未发布可放弃本地批次并保留回执，提示用户到平台删除草稿；已发布只能跳到平台管理。结果未知或操作中不允许替换、放弃或重发。小红书图片同样可在上传前移除或替换，原素材不物理删除。封面只检查所选平台对应比例，缺失就在该平台卡片提示并提供“去生图中心补”链接，未选平台缺图不阻断。生图中心选定已关联作品的版本时同步采用。
2. **通用文案**：标题、简介、话题标签只填一次，作为各平台版本来源。提供「AI 帮我写」，AI 未接入时禁用。按配置生成话题格式；标题/简介按模板字数限制检查，超长明确标出，不在半句话处硬截断。接入 AI 后可改写，改写仍须检查上限。
3. **平台版本**：勾选平台后自动生成标题、简介、话题、封面映射和发布时间。优先本月推荐时段，其次模板默认时间，无有效时间则明确显示「确认后立即发布」。平台限制或格式未核验不得伪装成已就绪。
4. **平台卡片**：正常卡片默认收起，一行显示「平台｜标题摘要｜封面比例｜发布时间｜状态」。超字数、缺封面、模板未核验、账号未就绪等问题自动展开并标黄。用户可收起查看；问题清单变化后再次自动展开。展开不等于修改；用户修改任一字段后标「已单独修改」，之后通用文案变化不覆盖整个该平台设置。提供「恢复为通用文案」，重新生成文案、话题和默认时间，取消单独修改。
5. **上传到各平台**：这是用户明确触发的发布准备操作。服务通过 `src/browser/` 逐个平台打开后台，上传成片和封面并填写文案/时间，停在最终发布按钮前。有草稿功能优先存草稿；是否具备草稿功能及停留方式，在第 13 章第 11 步打开真实页面确认，不凭记忆实现。此按钮绝不点击发布。
6. **审核区**：并排展示每个平台真实填好页面的截图和状态：上传中 / 已就绪待发布 / 失败及原因 / 已过期。截图保存为资产，回执记录截图资产 ID、上传完成时间及材料版本。上传完成满 2 小时未发布即「已过期，需重新上传」；阈值从 `config/parameters.yaml` 的 `publishUploadExpiryHours` 读取。每个平台独立判断：只看自己使用的标题、简介、话题、时间、对应比例封面、成片、确认稿、模板和账号状态。修改其他平台材料不使它作废；例如换 16:9 只作废 YouTube，抖音 3:4 截图仍有效。
7. **全部发布**：用户核对截图并确认一次，服务只对当前「已就绪待发布」且截图、材料和期限仍有效的平台逐个点击发布。一个平台失败不影响其他平台。回执沿用平台审核中、已发布、失败、结果待核对等状态；仅允许重试已核实未发布且 safeToRetry 的单个平台，成功/审核中/结果未知不可重发。失败上传可单独重新上传；发布失败需核对未发布及截图仍有效，过期则先重新上传。上传、全部发布与重试有版本检查及幂等请求 ID；普通编辑自动保存，不要求修订号。

**自动保存**：编辑即自动保存，删去“保存准备”和“新建批次”。“最近的发布记录”只供回看，选择作品自动恢复其当前准备。“AI 帮我写”直接使用当前输入，不要求先保存。用户只看到“上传到各平台”和“全部发布”两个主要操作按钮。

**能力边界**：前端与契约阶段不接真实平台、AI 或数据库。自动保存不可用时明确显示原因；AI、上传到平台、发布按服务能力禁用；合法但尚未接入的操作返回 503，不能用模拟成功替代真实回执。接口失败使用中文说明，保留编辑内容。

#### 6.5.2 图文发布 ✅

| 来源 | 流程 |
|---|---|
| 公众号、抖音图文、X 的排版确认稿 | 选择作品后只需选平台，采用排版中心的唯一确认快照。标题、正文、配图及封面只读；其余话题、时间按模板生成。需要改正文就退回排版中心。之后沿用上传、截图审核、过期控制、全部发布与单平台重试流程。 |
| 小红书图文笔记 | 图片由用户自己制作并上传，标题、正文和话题使用通用文案；选平台后生成版本，支持单独修改及恢复。之后流程与视频相同。 |

图文发布成功后记录真实平台作品 ID，关联同一作品（6.8.5）；上传完成不代表已发布，不能提前建立成功发布记录。

### 6.6 互动收件箱（只读）✅

- **待回复的判定（U9 用户批准变更）**：允许手动「标为已回复」或「不用回（低价值）」，手动标记优先于平台证据，并进入可撤销的已归档列表；归档不计入总控台和收件箱待回复。「去回复」先打开已核实入口，再标为已回复并归档，复制名字与评论前 20 字，显示 10 秒撤销提示。归档后同一会话出现有明确 ID/时间的新对方消息，重新进入待回复并标注「有新消息」。无手动覆盖时，私信以完整的会话末条发送者、评论以本人回复证据判断，证据不足仍为未知。撤销恢复平台证据，不伪造平台未回复状态。手动低价值仅记录，不自动修改 AI 分类规则。

- AI 把每条消息归为三类：

| 分类 | 去向 |
|---|---|
| 商单线索 | → 商单列表 + 推送到总控台"今日行动" |
| 有价值的问题和观点 | → 一键同步到选题中心；同时汇总为"需求主题" |
| 其他（普通称赞、垃圾信息等） | → 忽略，**不自动回复** |

- **全程只读**，不在平台上做任何操作。

### 6.8 数据底座

#### 6.8.1 采集方式 ✅

- **AI 调用浏览器打开各平台创作者后台，读取页面数据**
- 不使用平台 API
- **采集方式按平台标注**，写在平台配置里，程序按标注执行：

| 平台 | 采集方式 |
|---|---|
| 抖音 | 截图（一张截图登记一次） |
| 小红书 | 截图 |
| B 站 | **导出 CSV**（近期稿件对比，含封标点击率和 3 秒跳出率）+ 粉丝页截图 1 张 |
| YouTube | **导出 CSV**（高级模式，默认过去 28 天）+ 信息中心截图 1 张（订阅总数） |
| 视频号 | **导出 CSV × 2**：单篇视频（近 30 天）+ 关注者数据（近 7 天）；发图文后加单篇图文 |
| 快手、TikTok、X | 🟡 默认截图；首次发布后看后台有没有可用的导出，再确认 |
| 公众号 | 🟡 开始运营后标注 |
- 作品列表页是采集入口：**列表页每天全量抓**，拿到"近 30 天有哪些作品"、发布时间和列表上能看到的指标；**详情页只在作品到达 D1 / D3 / D7 / D21 当天，以及被标为异常时才进入**。每天的页面访问少很多，抓得快，也更不像机器。检查点当天详情页没抓到的，第二天继续抓，按 7.2 标记为补数据

#### 6.8.2 调度 ✅

| 项目 | 规则 |
|---|---|
| 主抓取 | 每天 **10:32–10:45** 之间随机开始，所有平台整体抓取一次 |
| 为什么选这个时间 | 抖音账号级数据每天 10:00 更新前一日数据；小红书基础数据截止到当日 0 点。10:32 之后，两个平台都已经是完整的前一日数据 |
| 失败重试 | 11:00、11:30 各一次 |
| 仍然失败 | 健康条标红，写明原因，提供 [立即重抓] |
| 数值的截止时间 | 不逐条记录。作品数据用"抓取日期"作为数据日期；**账号级数据记到平台标注的日期**（比如抖音 10:00 更新的是前一日，就记为前一日），避免粉丝图和发布日期错位一天 |
| 同一天多次抓取 | 重试或 [立即重抓] 产生的多次结果，以当天最后一次成功的为准 |

#### 6.8.3 采集范围 ✅

- **作品级**：近 30 天发布的作品，列表页每天更新，详情页按检查点更新（见 6.8.1）
- **30 天以外**：停止抓取，**已抓取的历史数据永久保留**，用作基线计算的样本
- **账号级**：每天抓取（粉丝、账号趋势等）
- **作品下架**：作品被删除或设为仅自己可见、从列表页消失时，保留已有数据并标记「已下架」，**照常计入基线和命中率**（否则表现差的作品被删后，数据会越来越好看）
- **低频数据**：粉丝画像（性别、年龄、地域）每月一次；观看时段分布每月一次

#### 6.8.4 存储原则 ✅

每个数据点存成一行（长表）：

```
发布记录ID × 抓取日期 × 发布后第N天 × 指标名 × 数值
```

这样平台新增或删除指标时，**只需要改指标字典，不用改数据库结构**。

**空值规则（全平台通用）：** 页面显示「数据不足」「—」或导出缺失的数值，**一律存为空值**，界面显示「—」，**不参与基线、倍数和异常计算**；平台明确显示为 0 的才记 0。（记成 0 会拉低中位数，并误报「可能被限流」。）

#### 6.8.5 作品自动关联 ✅

采集时发现的每条作品，都要挂到「作品 → 选题」上，否则命中率和 🔥 无从计算。**全自动，不需要用户手动关联。**

| 情况 | 处理 |
|---|---|
| 通过发布中心发布的 | 发布时就记下平台作品 ID，采集时直接对上 |
| 用户在平台上手动发布的 | 采集到新作品时，**先用发布中心为各平台生成的标题精确匹配**；对不上再由 AI 按**标题 + 发布时间（前后 2 天内）**和已有作品匹配，同一内容在多个平台的发布记录归到同一个作品下 |
| 匹配不上的 | AI 从标题提炼一句选题，**自动新建选题和作品**，标记为「自动建立」 |

匹配依据的平台作品标识：B 站用标题 + 发布时间；YouTube、视频号用视频 ID；截图类平台用列表页的标题 + 发布时间。

#### 6.8.6 首次上线的历史导入 ✅

按“重新起号”方式开始：**固定起号日为北京时间 2026-09-17**，早于这天的作品忽略：

- 首次只建档起号日及以后发布的作品；每条作品仍只跟踪发布后 30 天，之后停抓保留历史；先按发布时间过滤，再做识别结果入库、作品关联和选题建立。不扫描更早历史；旧置顶作品也必须过滤
- 发布 **21–30 天**的作品：当前累计值和第 21 天相差不大，记为 **D21（标记为「补录」）**，进入 D21 基线样本
- 首次导入时超过 30 天的作品：不建档、不建选题、不写数值、不进入基线。上线后已采集作品自然变老时保留已存历史，不做删除
- 真实的 D21 样本满 20 条后，补录数据自动退出基线
- 补录作品**只进基线，不计入命中率**（没有 D3，而且是上线前的选题）
- 发布不满 21 天的：正常进入每日采集
- 历史作品同样按 6.8.5 自动建选题，作为「偏好（历史选题）」的初始样本
- D3、D7 基线没有补录来源，从上线后的新作品开始积累；样本不足 20 条时用已有的全部作品，不足 5 条时显示「样本不足」

## 7. 选题命中率与复盘算法 ✅

### 7.1 计入范围

| 平台 | 命中标准 | 说明 |
|---|---|---|
| 抖音 | **播放量** | **包含平台扶持流量。** 平台扶持说明这个话题本身讨论度、关注度高，是优质选题的信号，抖音不会随便给扶持。**视频和图文都计入，合并算一个命中率；基线按形式分开**（见 7.2） |
| 公众号 | **阅读人数** | 去重后的人数，不用阅读次数 |
| 其他平台 | 不计入 | 仍按各自的复盘主指标（见第 3 章）显示 D3 / D7 / D21 倍数和走势类型，只做参考 |

### 7.2 三个检查点与同龄基线

| 检查点 | 作用 | 基线 |
|---|---|---|
| **D3** | 初判：开局强不强 | 最近 20 条作品**发布后第 3 天**累计数据的中位数 |
| **D7** | 中判：主推流期结束后的走势；用于本月的预估命中率 | 最近 20 条作品第 7 天累计数据的中位数 |
| **D21** | **终判**：命中或未命中。抖音长尾推荐很多，所以以第 21 天为准 | 最近 20 条作品第 21 天累计数据的中位数 |

```
某检查点倍数 = 本作品在该检查点的累计值 ÷ 同一检查点的基线
```

计算规则：
- **抖音视频和图文：基线分开，倍数合并**。视频和视频比、图文和图文比，算出各自的倍数后，再放在一起判命中、算一个命中率。命中衡量的是**选题**，但图文和视频的播放量级不同（图文的扶持流量也明显更多），共用一条基线时，倍数反映的会是内容形式而不是选题。分开比较后，「图文试选题」才真正有效：一条图文达到同类图文的 2 倍，才说明这个选题值得做成视频
- 作品卡片上标注内容形式（视频 / 图文），便于区分
- 基线**不含作品本身**。同形式的作品不足 20 条时，用已有的全部作品算中位数；**不足 5 条时不算倍数**，显示「样本不足」（比如刚开始发图文时，第一条图文没法和自己比）
- **基线按平台、按内容形式分开**：每个平台只用本平台、同一形式的作品算基线（视频号的视频和图文，主指标本来就不同）
- D21 的基线**只使用已经满 21 天**的作品
- 某个检查点当天抓取失败时，用之后最近一天的数据补上，并做标记
- "发布后第 N 天"按发布时间计算，取发布满 N×24 小时后的第一次抓取
- **倍数到点即定格**：作品到达某个检查点时，用当时的基线算出倍数并保存，之后基线变化不回溯，已终判的结论不会变
- 平台只给发布日期、没有具体时间的（比如视频号），按发布当天 0 点计算

### 7.3 走势分类（D3 × D21）

| D3 倍数 | D21 倍数 | 类型 | 含义 |
|---|---|---|---|
| ≥ 1.5 | ≥ 1.5 | 🚀 **爆发型** | 选题和开头都强 |
| < 1.5 | ≥ 1.5 | 🌱 **长尾型** | 选题有持续需求，往往由搜索带动，适合反复做或做系列 |
| ≥ 1.5 | < 1.5 | 🎆 **昙花型** | 开头抓人，但后劲不足 |
| < 1.5 | < 1.5 | 未命中 | — |

**命中 = 爆发型 + 长尾型。** D7 不参与分类，只用来显示走势和计算预估命中率。

### 7.4 命中率

```
已定稿命中率 = 当月首发选题中的命中数 ÷ 当月已完成 D21 终判的首发选题数
预估命中率   = 本月首发选题按 D7 倍数 ≥ 1.5 估算（标为"进行中"）
```

- 总控台同时显示**已定稿命中率**（上月及更早）和**预估命中率**（本月），旁边写样本数，例如 `命中 4 / 已终判 9`（上月末发布的作品要到本月 20 号左右才终判完）
- **按选题计数**：同一个选题在同一平台只算**首发**那条作品（通常是先发的图文）。后来做成的视频照常显示倍数和走势，但不重复计入命中率，否则「先试图文、好了再做视频」会让同一个好选题算两次
- 分开统计 **🔥 选题的命中率**和**非 🔥 选题的命中率**：前者衡量 AI 的判断，后者作为对照。**对照组只算选题中心里的非 🔥 候选**，「自动建立」的选题不计入任何一组
- **按平台各算一个**：抖音一个（视频和图文合并），公众号一个，不互相合并
- **样本要求**：累计 20–30 个选题之前，系统只记录，不下结论

## 8. 指标字典

### 8.0 分级说明

| 级别 | 含义 | 处理方式 |
|---|---|---|
| 🟥 核心 | 每天监控，参与同龄基线对比，在总控台重点展示 | 列表页有的每天抓；只在详情页有的，在检查点抓（见 6.8.1） |

### 8.1 抖音 ✅ 已定稿

**筛选思路：** 一个指标对应一个决策，包括选题对不对、开头好不好、内容撑不撑得住、有没有价值感、能不能转粉。

#### 作品级

| 级别 | 指标 | 漏斗阶段 | 用来回答什么 |

| 🟥 | **5 秒完播率** | 留存 | 开头的钩子成立吗？ |
| 🟥 | **平均播放占比** | 留存 | 整体留存。比完播率更适合跨作品比较，因为完播率受时长影响太大 |
| 🟥 | **搜索流量占比** | 吸引 | 是不是长尾型作品 |
| 🟥 | **涨粉量** | 转化 | 带来关注了吗？ |

| 🟨 | 平均播放时长 | 留存 | 和平均播放占比互相印证 |
| 🟨 | 脱粉量 | 转化 | 作品是否劝退老粉 |

| ❌ | 弹幕量、弹幕分析、不感兴趣量 / 率、单条作品的观众画像、评论热词、同类作者对比、播放量贡献 TOP3、合集数据、直播数据（待确认是否做直播，默认舍弃） | — | — |

| 分组 | 包含的来源 | 说明什么 |

| 级别 | 指标 |

### 8.1.1 抖音（图文）✅ 已定稿

**第一性：** 抖音图文在推荐流里先露出首图，用户决定看不看，然后左右滑看图、展开看文案。所以它的漏斗是：**首图被点开 → 不划走 → 看图、看文案 → 互动 → 关注**。和视频最大的区别是：**图文有单条作品的封面点击率**（视频只有账号级），而且用「划走率」代替「2 秒跳出率」。

#### 作品级

| 级别 | 指标 | 漏斗阶段 | 用来回答什么 |
|---|---|---|---|
| 🟥 | **播放量**（含平台扶持流量） | 结果 | 选题命中的判定标准（和图文自己比，倍数和视频合并判命中） |
| 🟥 | **封面点击率** ⭐ | 吸引 | 首图加标题能不能让人点进来；这是抖音上**唯一的单条作品封面反馈** |
| 🟥 | **划走率** | 吸引 | 首图和开头文字有没有留住人，相当于视频的 2 秒跳出率 |
| 🟥 | **平均浏览图片数** | 留存 | 多图作品看到第几张；单图作品恒为 1，只作参考 |
| 🟥 | **收藏量** | 互动 | 内容有用的最强信号 |
| 🟥 | **涨粉量**（吸粉量） | 转化 | 带来关注了吗？ |
| 🟨 | 文案展开率、文案完读率 | 留存 | 文案有没有被看、看没看完 |
| 🟨 | 评论进入率 | 互动 | 图文的讨论度（样本里高达 40%） |
| 🟨 | 点赞量 / 率、评论量 / 率、分享量 / 率、收藏率 | 互动 | 互动细节 |
| 🟨 | 流量来源（按 4 组归并，同视频）、搜索流量占比 | 吸引 | 流量结构、是否长尾 |
| 🟨 | 平台扶持流量 | 吸引 | 优质选题信号（同时计入播放量；样本里 11.3 万播放中有 9.1 万来自扶持） |
| 🟨 | 脱粉量 | 转化 | 是否劝退老粉 |
| 🟦 | **搜索关键词**、**看完作品后常搜的词** | 选题输入 | 同视频 |
| ❌ | 下载量、不感兴趣量 / 率、涨粉率 / 脱粉率（可以算出来）、评论热词、单条作品的观众画像 | — | — |

**采集路径（截图）：**
1. 作品管理列表页：图文作品直接显示播放、点赞、评论、分享、收藏、划走率、文案展开率、平均浏览图片数、吸粉量（视频作品同一位置显示完播率和 2 秒跳出率）
2. 作品详情 → 流量分析：1 张截图补封面点击率、文案完读率、评论进入率、各项互动率、流量来源、扶持流量、搜索词
3. 作品详情 → 观众分析：补脱粉量

### 8.2 小红书（视频笔记）✅ 已定稿

**第一性：** 小红书是**双列信息流**，用户先看到封面加标题，再决定点不点。

```
观看量 ≈ 曝光量 × 封面点击率
曝光低 → 平台没推（选题或账号权重的问题）
曝光高、点击率低 → 封面或标题的问题
```

**系统意义：** 抖音没有单条作品的封面点击率，**小红书是整个系统里单条作品封面反馈的主要来源**（对应 3:4 封面）。小红书的封面点击率衡量的是**"封面 + 标题"的组合**，所以每条作品必须同时存档标题。

#### 作品级

| 级别 | 指标 | 漏斗阶段 | 用来回答什么 |
|---|---|---|---|
| 🟥 | **封面点击率** ⭐ | 吸引 | 封面加标题能不能让人点进来，这是**小红书最核心的考核指标** |
| 🟥 | **曝光数** | 吸引 | 平台推了多少 |
| 🟥 | **观看数** | 结果 | 最终拿到了多少观看 |
| 🟥 | **2 秒退出率** | 留存 | 偏高时往往说明**开头和封面承诺的内容对不上** |
| 🟥 | **收藏数** | 互动 | 内容有用的最强信号，也会带动搜索长尾 |
| 🟥 | **涨粉数** | 转化 | 带来关注了吗？ |
| 🟨 | 5 秒完播率、完播率、平均观看时长 | 留存 | 留存细节 |
| 🟨 | 点赞、评论、分享、互动率 | 互动 | 互动细节 |
| 🟨 | 观看来源（视频推荐、搜索、首页推荐、其他） | 吸引 | 判断是不是长尾 |
| 🟨 | 观看的粉丝占比 | 吸引 | 破圈程度 |
| 🟨 | 同类中位数（封面点击率、互动率、5 秒完播率、平均观看时长） | 参考 | 平台提供的外部参照，**只作参考**，仍以"和自己的历史比"为主 |
| 🟨 | 笔记诊断文字 | — | 原样存档 |
| ⬜ | 离开趋势曲线 | — | 深度复盘时跳回后台查看 |
| ❌ | 画质得分（一次性的技术问题）、弹幕、单条作品的观众画像、账号诊断雷达图、活跃粉丝、直播数据、发布数据、笔记灵感 | — | — |

#### 账号级

| 级别 | 指标 |
|---|---|
| 🟥 | **总粉丝数、净涨粉**、新增关注、取消关注 |
| 🟨 | 主页访客、**主页转粉率**（衡量主页装修和简介能不能把访客变成粉丝） |
| 🟦 每月 | **观看时段分布** → 用作发布中心的默认发布时间 |
| ⬜ 每月 | 粉丝的性别、年龄、地域 |
| ❌ | 粉丝兴趣分布、账号诊断 |

**采集路径：**
1. 「数据看板 → 内容分析」列表页：**一页就能拿到所有笔记的曝光、观看、封面点击率、点赞、评论、收藏、涨粉、分享、人均观看时长**
2. 只为补 2 秒退出率、5 秒完播率、观看来源，才逐条进入「笔记数据详情」

**采集注意：** 不要自己用"观看 ÷ 曝光"去算封面点击率，两者口径不同，**一律直接取平台显示的值**。

**第一性：** 公众号有两套分发机制：粉丝在消息列表里看到推送，以及推荐和朋友圈带来的社交传播。

| 级别 | 指标 | 用来回答什么 |
|---|---|---|
| 🟥 | **阅读人数** | 选题命中的判定标准 |
| 🟥 | **打开率**（阅读人数 ÷ 送达人数） | 标题和封面能不能打动粉丝，这是公众号上封面点击率的替代指标 |

| 🟥 | **分享数** | 社交传播的动力 |
| 🟥 | **完读率**（待验证后台是否提供） | 文章撑不撑得住 |
| 🟥 | **文章带来的新增关注** | 转化 |

| 账号级 🟥 | 累计关注、净增关注、新增关注、取消关注 | — |

### 8.5 B 站 ✅ 已定稿

**第一性：** B 站以横版视频为主，首页推荐是"封面 + 标题"的卡片，用户先看卡片再决定点不点。B 站把这两者合称**"封标"**，印证了"封面点击率衡量的是封面 + 标题组合"的判断。

**系统意义：** B 站和 YouTube 是**横版封面（16:9 / 4:3）的单条作品反馈来源**（小红书对应 3:4；抖音只有账号级封面点击率）。B 站只给星级，YouTube 给真实百分比。B 站不计命中率，只做跟随分发。

**平台特点：**
- 封标点击率**只给同类比较后的星级**（如 4.4 星、超过 87% 同类稿件），不给原始百分比
- 播放来源只按设备分（移动、PC、H5、TV），**没有推荐 / 搜索的拆分**，无法判断长尾（B 站不计命中率，影响不大）
- 各页面更新时间不同（播放分析当天更新、数据概览和粉丝页 T-1、转粉分析中午 12 点更新）。**接受延迟，不记录每个数值的截止时间**
- 正在推流的作品，不同页面在不同时刻截图会出现播放量不一致，这属于正常现象；**播放量统一取近期稿件对比（CSV）的数值**

#### 作品级

| 级别 | 指标 | 来源 | 用来回答什么 |
|---|---|---|---|
| 🟥 | **播放量** | CSV | 最终拿到了多少播放 |
| 🟥 | **封标点击率** ⭐（星级） | CSV | 横版封面加标题能不能让人点进来。只记星级、只取「整体」；基线用星级中位数 |
| 🟥 | **3 秒跳出率** | CSV | 开头能不能留住人（B 站口径是 3 秒，不和其他平台比） |
| 🟥 | **平均播放进度** | CSV | 占总时长的百分比，衡量内容撑不撑得住 |
| 🟥 | **收藏量** | CSV | B 站用户觉得有用就会收藏，是最强的价值信号 |
| 🟥 | **涨粉量** | CSV | 带来关注了吗？ |
| 🟨 | **游客播放占比**、粉丝观看率 | CSV | 观众构成，在作品卡片上显示。粉丝少时恒接近 100%，**粉丝涨起来后再评估是否升级为核心**；真正衡量破圈规模的是"播放量 × 游客占比"（游客播放量） |
| 🟨 | 点赞、评论、弹幕、投币、转发 | CSV | 互动细节 |
| ⬜ | 流失趋势、留存分布曲线 | — | 作品异常时跳回后台查看 |
| ❌ | 数据解读文字、流量状态、互动率与播转粉率（可由 CSV 算出，不单独采集）、播放来源（设备）、发稿后 48 小时播放趋势、近 7 天总播放 vs 粉丝播放、单条作品的观众画像与兴趣词云、提升思路推荐 | — | — |

#### 账号级

| 级别 | 指标 |
|---|---|
| 🟥 | **粉丝总数、净增粉丝**、新增关注、取消关注（粉丝分析页） |
| ⬜ 每月 | 粉丝画像：性别、年龄、地域 |
| ❌ | 账号播放量、空间访客、收益（目前为 0）、专栏数据（不做专栏）、活跃时段、粉丝粘性、粉丝排行、领取勋章 / 充电粉丝数、粉丝来源、游客画像、账号诊断雷达图 |

**采集路径：**
1. 「稿件分析 → 播放分析 → 更多稿件对比」进入近期稿件对比，选「历史累积数据」，「自选指标」已勾选**封标点击率、3 秒跳出率**，点右上角**导出 CSV**。一个文件拿到所有稿件的核心和次核心指标，**不用再逐条进详情页**

### 8.6 YouTube ✅ 已定稿

**第一性：** 横屏长视频在 YouTube 上靠**缩略图 + 标题**被点开（首页、推荐、搜索），所以缩略图点击率直接衡量 16:9 封面。

**系统意义：**
- YouTube 给的是**真实的缩略图点击率**，是 16:9 封面最好的反馈来源
- 用户以后打算开通创收，但目前距离门槛还远，**暂不跟踪创收进度**

**默认规则：**
- 所有作品**默认按横屏长视频处理**。如果某条被识别成 Shorts，照常记录导出里有的数据，缺失的留空，不另设一套指标
- 时间范围用高级模式**默认的「过去 28 天」**。这个范围比抓取当天晚约 2 天，可以接受（YouTube 不计命中率，其他平台也只跟踪 30 天内的作品）
- 发布满 28 天后，最早几天的数据会移出统计范围，第 29–30 天的数值可能略有回落，属于正常

| 🟨 | **观看时长（小时）** | 以后开通创收时的门槛指标，先记录 |
| 🟨 | 平均观看时长、赞、评论、分享 | 留存和互动细节 |

| ❌ | 继续观看率（导出里没有）、深度观看次数、实时 48 小时数据、热推、赞和不喜欢的比率、片尾画面点击率、混剪、唯一身份观看者、设备类型、字幕语言、观众还看过的内容、估算收入、YouTube 搜索字词 | — |

## 10. 数据模型（建议）

```
选题 Topic ──1:N── 作品 Content ──1:N── 平台发布记录 Post ──1:N── 作品数据快照 PostSnapshot
                       │
                       ├──1:N── 素材 Asset（生图中心产出，排版中心、发布中心取用）
                       └──1:N── 排版稿 Layout（排版中心产出，确认后送进发布中心）
平台发布记录 Post ──1:N── 互动消息 Message（评论）──0:1── 商单 Deal
平台账号 Account ──1:N── 互动消息 Message（私信）──0:1── 商单 Deal
平台账号 Account ──1:N── 账号日数据 AccountDaily
指标字典 MetricDefinition（被快照和账号日数据引用）
抓取日志 CrawlLog（驱动"数据更新时间"和健康条）
选题输入 TopicSignal（搜索词、看完后常搜词、有价值的评论 → 选题中心）
```

| 实体 | 关键字段 |
|---|---|
| **Topic 选题** | id、方向描述（1–2 句）、信息来源（链接）、输入渠道、状态（候选 / 选中 / 跳过 / 已发布）、是否 🔥、🔥 理由、是否探索位、**是否自动建立**、创建时间 |
| **Content 作品** | id、topic_id、内容形式（视频 / 图文）、主标题、计划发布日期（可选）；封面和配图通过素材 Asset 关联 |
| **LayoutDocument 排版稿** | 一个文档含公众号 / 抖音图文 / X 三个版本（variants），各版独立正文、素材、状态与更新时间；每次确认存独立快照 |
| **RawRecord 原文记录** | id、平台、作品 id（可空）、数据日期、类型、JSON 内容、来源截图或导出文件路径；保存诊断文字、粉丝画像、观看时段分布。搜索词仍进 TopicSignal |
| **Asset 素材** | id、content_id（可选）、topic_id（可选）、用途（视频封面 / 公众号封面 / 插图 / 抖音图文配图 / 自由 / 上传）、比例、文件、来源（AI 生成 / 用户上传）、提示词、版本、是否选定、创建时间 |
| **Post 平台发布记录** | id、content_id、平台、平台作品 ID、发布时间、平台版标题、链接、各检查点倍数（定格）、走势类型、是否命中、是否首发、是否已下架 |

### 11.3 浏览器使用规则 ✅

- 可以用后台无界面模式；网络不做限制，正常使用即可。
- 只看页面和截图，不调用平台内部接口，不用 fetch，不拦截网络请求。
- 模拟正常用户节奏：动作之间随机间隔、分段滚动、在页面停留；一次只开一个平台，平台之间随机间隔。每天页面数设上限，写进 config；详情页只在 D1 / D3 / D7 / D21、补抓检查点或异常时打开。
- 出现验证码、滑块、风控、异常登录提示时：停止该平台，记入「需要你处理」清单，继续抓其他平台；这一轮全部结束后发一条 Mac 通知，列出所有待处理项。用户处理完后用一个命令让这些平台接着抓。不自动破解。
- 不自动输入密码；发布时像人一样逐步输入和上传。
- 抖音、小红书、B站、YouTube 直接使用 ego 自己保存的登录，不用 Network.setCookies 或 addScriptToEvaluateOnNewDocument 注入；cookie 文件只作为备份。
- 视频号需要登录时自动点「微信快捷登录」，将“请在微信里确认登录”记入「需要你处理」清单并通知用户；用户在浏览器外确认，检测到登录成功后自动继续。当天 23:00 前未确认则失败，原因写“未确认登录”。browser:check 显示“需要微信确认”不算错误。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 平台登录态失效 | 当天抓取失败 | 健康条提示原因 + [立即重抓]；自动重试两次 |
| 平台后台改版 | 指标位置或名称变化，导致识别失败 | 指标字典与代码解耦；截图存档便于排查 |
| 浏览器自动化触发风控 | 账号风险 | 抓取时间随机；详情页只在检查点进入；只读不写；发布必须人工确认 |
| AI 识别错误 | 数据失真 | 一图一登记；截图存档可回溯；数值明显异常（比如单日变化过大）时提示复核 |
| 冷启动样本不足 | 基线、🔥 和命中率不准 | 首次导入补录 21–30 天的作品；20 条有 D21 结果后才开 🔥；20–30 个选题之前不下结论 |
| 发布自动化 | 平台限制或误发 | 必须用户一键确认；发布前预览；放在开发顺序的最后 |
| 抓取时机器没开机 | 当天无数据 | 健康条提示；开机后可以 [立即重抓]；视频号关注者数据导出近 7 天，可以自动补齐 |
| 作品自动匹配出错 | 选题和数据挂错 | 作品详情里可以改关联；自动建立的选题有标记，便于检查 |

## 13. 开发顺序 ✅

当前执行顺序、完成标准、状态和审查点统一见 [ROADMAP.md](ROADMAP.md)，以下为原始阶段划分；冲突以 ROADMAP 为准。

**排序原则：** 按依赖关系排，而不是按时间排（AI 开发速度快，不设工期）。
- **数据先行**：复盘、总控台、🔥 都依赖数据，所以数据底座最先做；它越早上线，历史样本积累得越早
- **先读后写**：只读的功能先做，平台上传/草稿和最终发布的真实写操作放在第 11 步
- **先抖音后其他**：抖音是主阵地；其他平台在同一套框架上加适配器
- **每个板块做完都能独立使用**，不等全部做完才可用

| 顺序 | 板块 | 内容 | 依赖 | 完成标准 |
|---|---|---|---|---|
| **1** | 基础骨架 | 数据库与数据模型（第 10 章）、配置文件加载（11.2）、浏览器登录态管理、抓取日志 | — | 能保存和读取在发平台的登录态（新平台在第 12 步接入时再加）；配置改了就生效 |
| **2** | 数据底座：抖音 | 截图 + AI 视觉采集（列表页 → 详情页）、长表存储、空值规则、定时调度与重试、作品自动关联（6.8.5）、首次历史导入（6.8.6） | 1 | 每天 10:32–10:45 自动抓完抖音的视频和图文；失败会重试并记录原因 |
| **3** | 数据底座：其余在发平台 | 导出类：B 站、YouTube、视频号（解析 CSV）；截图类：小红书（复用第 2 步的视觉采集） | 2 | 5 个在发平台每天自动更新 |
| **4** | 复盘引擎 | 同龄基线、D3 / D7 / D21 倍数、走势分类、已定稿 / 预估命中率、🔥 与非 🔥 分开统计 | 2（其他平台依赖 3） | 抖音每条作品都有倍数和走势类型；命中率可以算出来 |
| **5** | 总控台 | 健康条、平台趋势、粉丝、近期作品与商单（商单先显示 0）、洞察与异常中的作品数据异常 | 3、4 | 每天早上打开一页就能看清各平台情况 |
| **6** | 互动收件箱 + 商单列表 | 读取评论和私信（先抖音，再其他平台）、AI 三分类、商单列表、今日行动、需求主题 | 1；各平台评论和私信页面的结构，开发时由 Agent 自己打开页面识别 | 商单线索出现在今日行动里；有价值的问题汇总成需求主题 |
| **7** | 选题中心 | 读取 `选题输入渠道.md`、内置渠道（抖音搜索词、看完后常搜词、收件箱有价值的问题）、20 个候选含探索位、偏好（历史选题）、🔥 与理由 | 2、4、6 | 一次生成 20 个候选；作品满 20 条后出现 🔥 |
| **8** | 生图中心 | 各用途生图、聊天框改图、素材库（生成 + 上传） | 1 | 需要的图都能在这里做出来、存进素材库，可以直接拿去手动发布 |
| **9** | 排版中心 | 结构识别、排版风格、三个版本（公众号 / 抖音图文 / X）、各版本单独修改、按平台预览、人工确认 | 1、8 | 一篇文章能出三个版本，确认后的内容可以直接复制去手动发布 |
| **10** | 发布中心：发布准备 | 通用文案、自动平台版本与单独修改、封面映射、接收确认稿、自制图文、上传/截图审核的前端与接口契约 | 8、9 | 每个平台的标题、文案、图片都整理好，可以直接拿去手动发布 |
| **11** | 发布中心：一键发布 | 真实页面核验（含草稿能力）、逐平台上传与截图、过期重传、一次确认全部发布、单平台失败重试与真实回执 | 10 | 抖音一键发布成功，并自动关联到作品；再逐个平台加 |
| **12** | 新平台与新形式接入 | 快手、TikTok、X、公众号、小红书图文、视频号图文：首发后截图核对指标、标注采集方式，再加适配器 | 3 | 随首发随接入，不改核心逻辑 |

**为什么互动收件箱排在选题中心前面：** 商单直接带来收入；而选题中心的 🔥 要等作品满 20 条才开启，晚一点做正好让数据先积累。另外，收件箱里"有价值的问题"本身就是选题中心的内置输入。

## 15. 数据中心（抖音版）

### 1.1 范围
- 先只做**抖音**，视频和图文分开比。
- 只读页面：**不新增采集**，全部用已存的每日快照和检查点数据计算。
- 只做两件事：① 单条作品和平时比；② 找出哪个指标拖了后腿。
- 没有：整体进步趋势、封面对比、选题对比（以后再说）。

### 1.2 入口
- 顶部导航新增「数据中心」。
- 总控台「近期作品」点任意一条 → 打开数据中心里这条作品。
- 数据中心默认打开最近发布的一条抖音作品。

### 1.3 页面布局（从上到下，一屏看完）

**① 作品条**（一行）
- 左边：作品选择下拉（按发布日期倒序，可搜标题）。
- 中间：标题 · 视频/图文 · 发布日 · 今天是第 N 天 · `FIRE` 标签（如有）。
- 右边：当前倍数（到 D21 后定格），已命中显示橙色，否则黑色。

**② 播放量走势图**（主图，占最大面积）
- 横轴：发布后第 1–21 天。纵轴：累计播放量。
- 橙色实线：这条作品。
- 深灰虚线：同形式历史作品「同一天龄」的**中位线**。
- 浅灰色带：同一天龄的**正常范围**（P25–P75，中间一半作品落在这里）。
- D1/D3/D7/D21 画细竖线，标注检查点。
- 某天没抓到：线断开，不连、不补、不当 0。D8 的补抓只放在 D8，不挪到 D7。
- 样本不足（同形式、同天龄有数的作品 < 5 条）：那几天不画中位线和带，图上写「样本不足（x/5）」。
- 鼠标悬停：显示这天的本条值、中位数、正常范围、参与比较的作品数。

**③ 逐项对比**（找拖后腿）
- 顶部切换：D1 / D3 / D7 / D21，默认最近一个已到的检查点；没到的检查点灰掉不能点。
- 一行一个指标，每行显示：指标名 · 本条值 · 中位数 · 一根细针条（浅灰带 = 正常范围，黑色细针 = 本条位置）· 结论文字。
- 结论文字只用三种：**偏低 / 正常 / 偏高**（按指标“越大越好”还是“越小越好”判断，例如跳出率越小越好）。
- 排序：偏低的排最上面，一眼看到拖后腿的。
- 没有数：显示「—」和「没抓到」，不参与结论。样本不足：显示「样本不足」，不给结论。
- 指标用哪些：指标字典里抖音、在检查点有数的全部指标。互动类（点赞/评论/分享/收藏/涨粉）用「每千次播放」比，避免播放高的作品天然占优。

**④ AI 解读**（底部一块）
- 按钮「生成解读」，**点了才调用**，不自动生成。
- 生成后存下来，下次打开直接显示，并注明“基于 D7 数据，生成于 x 月 x 日”。
- 有新检查点数据后，按钮变为「用 D21 数据重新生成」。

### 1.4 计算规则
- **对比池**：抖音、同形式（视频/图文）、发布早于本条、不含本条自己的作品；其余沿用现有基线规则（补录作品在有数的天龄可参与，命中率规则不变）。
- **同天龄**：按发布后第 N 天对齐，天数口径与现有 D1/D3/D7/D21 完全一致。
- **中位数和 P25/P75**：只用这天有数的作品；分位数算法与现有基线中位数保持一致（同一个函数）。
- **样本不足**：参与作品 < 5 条，不显示中位线、范围和结论。
- **偏低/偏高**：低于 P25 = 偏低，高于 P75 = 偏高，其余 = 正常（越小越好的指标反过来）。
- **空值**：存空就显示空，任何地方都不当 0 算。
- **算的时机**：打开页面时现算，不建新的统计表（数据量小）；只新建一张表存 AI 解读。
- 指标字典 YAML 给每个指标**补一个字段**：越大越好 / 越小越好（只加字段，不改旧 id）。

### 1.5 AI 解读规则
- 程序先把数字算好（本条值、中位数、范围、偏低/正常/偏高、样本数），只把这张数字表交给 AI；**AI 不自己算数**。
- 输出固定四段，总共不超过 150 字：
  1. 一句话结论（比平时好/差/差不多）
  2. 拖后腿的 1–2 项（带数字）
  3. 可能原因（必须写“推测”）
  4. 下一条可以试的 1 件事
- 只能引用数字表里的数；样本不足的指标要明说“样本不足，不下结论”；没抓到的指标说“没有数据”。
- 全部正常时直接说“各项都在正常范围”，不硬找问题。
- 调用失败：显示“生成失败，可重试”，不影响页面其他部分。

### 1.6 视觉（遵守 design.md）
- 只用一个强调色：橙色 = 这条作品 / 已命中。中位线深灰虚线，正常范围用 line-soft 浅色带。
- 数字全部等宽字体；结论用文字，不用红绿色。
- 仅桌面宽屏。
