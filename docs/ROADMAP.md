# 开发追踪（ROADMAP）

> PRD 写“做什么”，这份文档写“做到哪了、下一步做什么、做完怎么算”。
> Codex 每完成一步就更新本文件的状态和记录；🔍 A/B/C/D 写汇报文件后继续，只有 E/F 等用户确认。

## 怎么用

- 状态：⬜ 未开始 · 🟡 进行中 · ✅ 完成 · ⏸ 等用户 · 🔍 等审查
- 一次只做一步。每步做完：自测完成标准 → `npm run check` 全绿 → 提交 git → 在下方「记录」写一行 → 进入下一步。
- 🔍 A/B/C/D：用大白话写汇报文件，说明做了什么、怎么验收、剩余观察项，然后进入下一步。只有 🔍 E（第 10 步完成、真实上传前）和 🔍 F（每个平台首次真实发布前）必须停下等用户确认。
- 发现 PRD 没写清楚或要改需求：停下问用户，不要猜，不要自己改 PRD 口径。
- 前端（总控台、选题、收件箱、商单、生图、排版、发布）已做好，数据入口在 `src/lib/workspace-service.ts`；生图、排版和发布准备已接真实数据库，其余待对应步骤接入。U 系列允许改界面，规则见 design.md 第 10 节。

### 2. 数据底座：抖音 🔍 A
- 当前状态（8dd91e5）：实现及首轮真实采集已提交；仅最近 30 天的 4 条视频、1 条图文入库，旧作品 0 条。`npm run check` 全绿（33 项 Vitest 及原有业务检查），数据库和 7 份备份均通过检查，本机 launchd 已加载。
- 用户已通过 A 代码审查；连续 3 天自动运行、用户随机抽 5 个数字与后续开发并行，不阻塞第 3 步；真实断网/登录失效与恢复仍待验。详见 [验收记录](verification/2026-10-17-douyin.md)。
- 做什么：
  1. 用 ego 打开真实抖音创作者后台，确认列表页、详情页的结构，截图存档（不凭记忆写）。
  2. 截图 + AI 视觉识别：列表页 → 需要时进详情页；AI 返回固定 JSON，Zod 校验；识别失败记为失败并写原因，不填估计值。
  3. 写入长表（一行一个数），空值按 PRD 规则处理；截图存文件，数据库只存路径。
  4. 定时：launchd 每天 10:32–10:45 随机时间开始；失败在 11:00、11:30 重试；每次都写抓取日志；抓完自动备份。
  5. 作品自动关联（PRD 6.8.5）、固定北京时间 2026-09-17 起号日，更早作品（包括置顶）不建档；每条作品跟踪 30 天后停抓保留历史（决定 #100）。
  6. 「需要你处理」清单：遇到验证码、滑块、风控提示或需要扫码/确认登录时，先停下这个平台、记进清单，接着做其他平台；这一轮全部做完后发一条 Mac 通知，列出要处理的事。用户处理完后，用一个命令（或总控台按钮）让这些平台接着抓。不自动破解。
  7. 全程遵守 PRD「浏览器使用规则」（模拟正常用户的节奏）。
- 完成标准：
  - 连续 3 天自动抓完抖音视频和图文，不需要人动手；
  - 故意断网或登出时，会重试并在日志里写清原因，不写假数据；
  - 用户随机抽 5 个数字和抖音后台对比，全部一致；
  - 人为制造一次“需要处理”（例如登出抖音），确认会进清单、发通知，处理后能接着抓完。
- 🔍 A 审查重点：采集框架是否能直接复用到第 3 步；有没有违反浏览器规则；数据和后台是否一致。
