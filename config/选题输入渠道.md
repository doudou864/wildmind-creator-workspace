# 选题输入渠道

## Agent 读取规则

- 每次推荐前读取本文，启用渠道是观察起点；开启“主动发现”时可搜索其他网站、平台和商品，并沿真实页面链接追原文。搜索入口、预算和角度规则读取 topic-workflow.yaml。
- 来源库观察与抖音搜索词、看后搜、主动同步的问题共同找实体；不能因采到新外站内容而抛掉已有需求词。搜索词可以成为实体，但不是答案或收益证据。
- 每条候选是一句“实体＋角度”：观众能挣钱/方便/省时/学习/避损，或产生强烈好奇；先判断愿不愿点开并继续看，选中后再考虑制作。
- 先起草，再独立复核兴趣、事实支持与不同观看理由，保留原文和真实链接。第一轮只展示句子，点击再看依据；不拿评分、大纲和长解释救弱题。
- 候选目标、探索建议、FIRE门槛读取 parameters.yaml；材料不足宁缺毋滥，不因探索配额扔掉好题。
- 历史已发布、想看/无感反馈用于避重和校准，不限定新方向；历史实际表现决定 FIRE，不合成加权分数。
- FIRE 理由必须包含同类历史作品的 D21 倍数，有走势类型则一并注明。
- 探索用于没做过的方向；新旧案例都可，没有近期证据不能声称当前热门。挂牌、成交、自述收入、可核实收益要区分。
- 不使用小红书笔记灵感、YouTube 热门趋势灵感页。

## 渠道配置

下面的 YAML 是页面读取的配置。内置渠道只开关；外部渠道可在选题面板按“标题 + 链接”增删改，保存后自动写回本文。手动修改本文后刷新页面。生成前读取配置与已采集线索；不会自动同步尚未选择的收件箱消息。

```yaml
channels:
  - id: open_discovery
    name: 主动发现
    enabled: true
    kind: builtin
    type: 网页搜索与原文追查
    location: 浏览器搜索与已观察的真实链接
    focus: 观众收益或强烈好奇的具体实体
    frequency: 生成选题时
    note: 固定渠道之外继续找，搜索摘要仅作为入口
  - id: search_keywords
    name: 抖音搜索关键词
    enabled: true
    kind: builtin
    type: 搜索词
    location: 抖音作品详情 · 流量分析
    focus: 观众主动搜索的需求
    frequency: 每天
    note: 用户通过哪些词找到了作品
  - id: followup_search
    name: 看完后常搜的词
    enabled: true
    kind: builtin
    type: 后续搜索
    location: 抖音作品详情 · 流量分析
    focus: 观众看完后还想知道什么
    frequency: 每天
    note: 延续已发布作品中的未解问题
  - id: valuable_messages
    name: 有价值的问题与观点
    enabled: true
    kind: builtin
    type: 评论与私信
    location: 互动收件箱 · 有价值的问题和观点
    focus: 高频问题、具体困惑和不同观点
    frequency: 每天
    note: 仅使用在收件箱主动同步的问题或需求主题
```

## 外部渠道模板

在上面的 channels 列表中追加条目；id 必须唯一，kind 使用 external。填写名称、启用、类型、位置、关注什么、读取频率、备注。未填写固定外部来源时，仍可通过已启用的“主动发现”搜索；停用的固定来源不主动追读。

示例字段（请替换为真实渠道后再启用）：

```text
id: 自定义唯一代号
name: 渠道名称
enabled: false
kind: external
type: 网站 / 创作者 / 社区
location: 可访问的完整来源地址
focus: 关注的问题
frequency: 每天 / 每周
note: 读取范围和补充说明
```
